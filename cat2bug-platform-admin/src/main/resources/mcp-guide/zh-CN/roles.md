## 项目角色

一个成员在项目里可以有多个角色，权限取并集。下表是系统默认角色的常见分工；管理员可能改过角色权限，**以实况里「你可执行的操作」为准**。

| 角色 | 通常负责 | 缺陷流程中的默认能力 |
|---|---|---|
| 项目创建人 / 项目管理员 | 管理成员与项目设置，统筹进度 | 全部：新建、修改、指派、修复、审核通过 / 驳回、关闭、重开 |
| 项目测试 | 写用例、执行测试计划、提缺陷、验证修复 | 全部流转操作；还能执行测试计划、写报告 |
| 项目开发 | 修复缺陷、关联代码提交 | 新建、指派、提交修复；**默认不能审核通过 / 驳回、关闭、重开** |
| 项目外部人员 | 客户或外部协作者反馈问题 | 只能新建与修改缺陷、查看用例与交付物 |

团队管理员、系统管理员在项目里也能操作，但通常不参与日常流转。

## 怎么选人

- **指派处理人**：缺陷类型是 BUG / 任务时，一般指派给负责该交付物的开发；需求一般指派给项目管理员或开发负责人。
- **指定审核人**（`repair_defect` 的 `review_by`）：一般是提缺陷的测试；不传时默认取缺陷创建人（提出 bug 的人）。
- 不确定选谁时，用 `list_project_members` 列出成员，把候选人和他们的角色告诉用户，让用户决定。

## 常见情况

- 用户是开发，却想「审核通过」：默认没有该权限，告诉用户需要测试或项目管理员来审核。
- 用户是外部人员：只能提缺陷，提完告诉他「已提交，项目成员会跟进处理」。
