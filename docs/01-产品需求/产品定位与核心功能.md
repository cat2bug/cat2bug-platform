# 产品定位与核心功能

本笔记说明 Cat2Bug-Platform 是什么、给谁用、有哪些功能域，以及每个功能域落在哪些前端视图、后端路由与 OpenSpec 规格上，便于快速定位代码。

## 一句话定位

Cat2Bug-Platform（猫陪我改 BUG）是一套永久免费开源、可完全私有化部署、以 AI 辅助的轻量级 BUG 管理平台，当前版本 1.1.0（见 `README.md`）。

## 目标用户

- 个人开发者与中小型软件开发团队（`README.md`「平台简介」）。
- 理念：免去重度项目管理，即开即用、学习成本低，专注缺陷跟踪。

## 技术形态（与功能相关的部分）

- 后端：Quarkus，唯一一套后端（`cat2bug-platform-{admin,system,framework,common}`，默认 Maven 构建，无需 profile），路由在 `cat2bug-platform-admin/src/main/java/com/cat2bug/admin/resource/`。原 Spring Boot 线已删除，留档 tag `spring-final-1.1.0`，见 [[ADR-010-移除Spring后端并统一模块命名]]。
- 前端：`cat2bug-platform-ui`，Vue 3.5 + Vite 6 + Element Plus + Pinia + vue-router 4（见 `cat2bug-platform-ui/package.json`）。
- 项目级页面统一挂在 `/{teamKey}/{projectKey}/{module}` 下，模块白名单见 `cat2bug-platform-ui/src/utils/project-module-path.js` 的 `PROJECT_MODULES`：`dashboard`、`defect`、`case`、`plan`、`report`、`document`、`module`、`notice`、`member`、`option`、`api`、`tools`、`code`。
- 术语与表名对照见 [[术语表]]。

## 前端与交付相关规格（非业务功能域）

`frontend-vue3-shell`、`frontend-vite-build`、`frontend-element-plus`、`frontend-lib-migration`、`frontend-keyboard-a11y`、`frontend-e2e-keyboard`、`spa-history-routing`、`backend-prod-packaging-slim`、`prod-docs-images-slim`、`spring-native-embedded-delivery`、`spring-native-graal-hints`、`retire-quarkus-delivery`（这三项随 Spring 线下线，变更 `retire-spring-and-unify-modules` 归档后移除）、`single-backend-layout`、`public-release-export`（该变更新增）、`quarkus-backend-parity`、`quarkus-git-repositories`、`quarkus-jvm-acceptance-gate`、`quarkus-native-slim-binary`（均在 `openspec/specs/`）。

## 关联产品

Cat2Bug-App（手机端）、Cat2Bug-Chrome（浏览器插件）、Cat2Bug-MCP（AI 通讯代理）、Cat2Bug-JLog（错误日志采集）、Cat2Bug-JUnit（自动化单元测试），见 `README.md`「关联产品」。
