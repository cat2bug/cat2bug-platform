# 术语表

本笔记把产品中的业务术语对应到代码标识、路由段与数据库表，所列条目均已在代码或迁移脚本中核实；功能全貌见 [[产品定位与核心功能]]。

表结构以 `cat2bug-platform-admin/src/main/resources/db/migration/`（H2）与 `db/mysql/`（MySQL）为准（初始化脚本 `V0_5_1__init.sql`，后续以 `V1_*` 增量迁移）。

## 组织与权限

| 业务术语 | 代码标识 / 路由段 | 表名 | 备注 |
|---|---|---|---|
| 团队 | `team`，`/system/team` | `sys_team` | 团队成员关系表 `sys_user_team`，团队内角色 `sys_user_team_role` |
| 项目 | `project`，`/system/project` | `sys_project` | 项目成员关系表 `sys_user_project`，项目内角色 `sys_user_project_role` |
| 成员 | `member`，`/system/member`；项目模块段 `member` | `sys_user` | 成员即系统用户；属于团队/项目靠上面两张关系表 |
| 团队路径键 | `team_key`，前端 `teamKey` | `sys_team.team_key` | 全局唯一；迁移 `V1_1_0_4__team_project_path_keys.sql`，历史数据回填为 `team-{id}` |
| 项目路径键 | `project_key`，前端 `projectKey` | `sys_project.project_key` | 团队内唯一（`team_id, project_key`），历史数据回填为 `project-{id}` |
| 路径键（统称） | `path key`，`cat2bug-platform-ui/src/utils/path-key.js` | — | 用于项目级 URL `/{teamKey}/{projectKey}/{module}` |
| 项目模块段 | `PROJECT_MODULES` | — | 见 `cat2bug-platform-ui/src/utils/project-module-path.js` |
| 邀请链接 | `invite`，前端 `/invite/:token`，后端 `/invite` | `sys_member_invite` | 字段 `token`、`scope`（团队/项目范围）、`role_ids`、`expires_at`、`revoked` |
| 角色 / 菜单 / 部门 / 岗位 | `role` / `menu` / `dept` / `post` | `sys_role`、`sys_menu`、`sys_dept`、`sys_post` | 菜单权限串如 `system:git:repo:list` 存于 `sys_menu.perms` |

## 测试与缺陷

| 业务术语 | 代码标识 / 路由段 | 表名 | 备注 |
|---|---|---|---|
| 缺陷 | `defect`，`/system/defect` | `sys_defect` | 软删除字段 `del_flag`（迁移 `V0_6_2_7`） |
| 缺陷合并 | `merge`，`POST /system/defect/merge` | 主缺陷更新 + 从缺陷软删 | 浅合并：选定主缺陷后按字段择优写入主记录，其余软删；不迁移日志/计划 CSV/甘特边；权限 `system:defect:merge`；日志类型 `MERGE` |
| 缺陷类型 | `defect_type`，`DefectConstants.DEFECT_TYPES` | `sys_defect.defect_type` | `BUG`（问题）、`TASK`（任务）、`DEMAND`（需求）；库里存序号 0～2 |
| 缺陷状态 | `defect_state`，`DefectConstants.DEFECT_STATES` | `sys_defect.defect_state` | `PROCESSING`(0) 处理中、`AUDIT`(1) 待验证、`RESOLVED`(2) **通过**、`REJECTED`(3) 已驳回、`CLOSED`(4) 已关闭、`CREATED`(5) **已创建**（仅无人）；`pass`→通过，`close`→关闭；`open` 有人→处理中、无人→已创建（看板未指派）；不强制通过后再关 |
| 缺陷日志 | `defect log`，`SysDefectLogStateEnum` / `DefectLogState` | `sys_defect_log` | 缺陷处理流转记录 |
| 存活时间 / 周期驳回次数 | `handleStartTime` / `handlePassTime` / `rejectCount`（派生，不落库） | 由 `sys_defect_log` 计算 | 周期锚点为最近一次 `CREATE`/`OPEN`；进行中终点为当前时刻，通过(`PASS`)与关闭(`CLOSED`)取本周期最晚一次并冻结；`rejectCount` 为本周期 `REJECTED` 条数；重开后重置。展示仅表格标题行与详情固定统计；数字色阶见团队「页面设置」 |
| 缺陷页面设置 | `defect_page_config` / `DefectPageSettings` | `sys_team.defect_page_config` | 团队级：启用的缺陷视图、存活/驳回色阶阈值与颜色、是否允许分享；入口在团队缺陷设置卡片；项目侧只读；设置页「重置」确认后立即用默认配置写库；同页还可维护模块闸门中的缺陷显示开关与名称 |
| 团队模块页面设置 | `module_page_config` / `ModulePageSettings` | `sys_team.module_page_config` | 团队级功能模块硬闸门与显示名：开关键 `case_plan`（一开关两名称）、`defect`、`deliverable`、`document`、`code`；文档另有 `maxUploadMb`（≤ `sys.upload.maxFileSizeMb`）；关闭后侧栏/API/MCP/工作台相关能力不可用，数据不删；见 [[ADR-026-团队功能模块闸门优先于角色菜单与项目MCP]] |
| 缺陷分享 | `defect shard`，前端 `/shard/defect` | `sys_defect_shard` | 代码拼写为 `shard`，含可选分享密码；分享图卡按属性 `sortOrder` 取第一个有可加载图的 `image` 字段（系统 `imgUrls` 与自定义图片共用排序，404 视为无图）。团队关闭分享时禁新建并拒匿名打开（文案「分享已关闭」） |
| 缺陷自定义字段 | `defect-fields`，`/system/project/{projectId}/defect-fields` | `sys_project_defect_field` | 项目级字段配置 |
| 缺陷页签 | `tabs`，`/system/tabs` | `sys_project_defect_tabs` | 用户在项目内保存的缺陷筛选页签 |
| 测试用例 | `case`，`/system/case` | `sys_case` | 类型在 `sys_case_type`（`case_type` 可空；`enabled` 1/0，默认启用）；评审标记 `review_status` 为空表示未评审。AI 生成用例提示词表 `sys_case_prompt`（`/system/CasePrompt`） |
| 用例评审 | 一次勾选批次，`/system/case-review` | `sys_case_review`、`sys_case_review_item` | 状态 `open` / `completed`。条目结论 `pending` / `passed` / `changes`。完成后纪要在 `report_markdown`。不是用例审批状态机，也不拦截加入测试计划。前端评审记录页 `case/reviews`、详情 `case/reviews/:reviewId`（用例页下拉「评审记录」，不进侧栏） |
| 测试计划 | `plan`，`/system/plan` | `sys_plan` | 主键 `plan_id` 为 36 位字符串 |
| 计划子项 | `plan item`，`/system/PlanItem` | `sys_plan_item` | 关联 `plan_id` 与交付物 `module_id` |
| 交付物 | `module`，`/system/module`；Open API 中叫 `deliverable`（`/api/deliverable`、`deliverableId`） | `sys_module` | 后端 i18n `module=交付物`；用例、计划子项通过 `module_id` 关联 |
