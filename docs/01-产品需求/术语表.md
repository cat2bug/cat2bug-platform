# 术语表

本笔记把产品中的业务术语对应到代码标识、路由段与数据库表，所列条目均已在代码或迁移脚本中核实；功能全貌见 [[产品定位与核心功能]]。

表结构以 `cat2bug-platform-admin/src/main/resources/db/migration/`（H2）与 `db/mysql/`（MySQL）为准（初始化脚本 `V0_5_1__init.sql`，后续以 `V1_*` 增量迁移）。

## 组织与权限

| 业务术语 | 代码标识 / 路由段 | 表名 | 备注 |
|---|---|---|---|
| 团队 | `team`，`/system/team` | `sys_team` | 团队成员关系表 `sys_user_team`，团队内角色 `sys_user_team_role` |
| 项目 | `project`，`/system/project` | `sys_project` | 项目成员关系表 `sys_user_project`，项目内角色 `sys_user_project_role` |
| 成员 | `member`，`/system/member`；项目模块段 `member` | `sys_user` | 成员即系统用户；属于团队/项目靠上面两张关系表 |
| 团队路径键 | `team_key`，前端 `teamKey` | `sys_team.team_key` | 全局唯一；迁移 `V1_1_0_4__team_project_path_keys.sql`，历史数据回填为 `team-{id}` |
| 项目路径键 | `project_key`，前端 `projectKey` | `sys_project.project_key` | 团队内唯一（`team_id, project_key`），历史数据回填为 `project-{id}` |
| 路径键（统称） | `path key`，`cat2bug-platform-ui/src/utils/path-key.js` | — | 用于项目级 URL `/{teamKey}/{projectKey}/{module}` |
| 项目模块段 | `PROJECT_MODULES` | — | 见 `cat2bug-platform-ui/src/utils/project-module-path.js` |
| 邀请链接 | `invite`，前端 `/invite/:token`，后端 `/invite` | `sys_member_invite` | 字段 `token`、`scope`（团队/项目范围）、`role_ids`、`expires_at`、`revoked` |
| 角色 / 菜单 / 部门 / 岗位 | `role` / `menu` / `dept` / `post` | `sys_role`、`sys_menu`、`sys_dept`、`sys_post` | 菜单权限串如 `system:git:repo:list` 存于 `sys_menu.perms` |

## 测试与缺陷

| 业务术语 | 代码标识 / 路由段 | 表名 | 备注 |
|---|---|---|---|
| 缺陷 | `defect`，`/system/defect` | `sys_defect` | 软删除字段 `del_flag`（迁移 `V0_6_2_7`） |
| 缺陷类型 | `defect_type`，`SysDefectTypeEnum` | `sys_defect.defect_type` | `BUG`（问题）、`TASK`（任务）、`DEMAND`（需求） |
| 缺陷状态 | `defect_state`，`SysDefectStateEnum` | `sys_defect.defect_state` | `PROCESSING` 待处理、`AUDIT` 待验证、`RESOLVED` 已解决、`REJECTED` 已驳回、`CLOSED` 已关闭 |
| 缺陷日志 | `defect log`，`SysDefectLogStateEnum` | `sys_defect_log` | 缺陷处理流转记录 |
| 缺陷分享 | `defect shard`，前端 `/shard/defect` | `sys_defect_shard` | 代码拼写为 `shard`，含可选分享密码 |
| 缺陷自定义字段 | `defect-fields`，`/system/project/{projectId}/defect-fields` | `sys_project_defect_field` | 项目级字段配置 |
| 缺陷页签 | `tabs`，`/system/tabs` | `sys_project_defect_tabs` | 用户在项目内保存的缺陷筛选页签 |
| 测试用例 | `case`，`/system/case` | `sys_case` | AI 生成用例提示词表 `sys_case_prompt`（`/system/CasePrompt`） |
| 测试计划 | `plan`，`/system/plan` | `sys_plan` | 主键 `plan_id` 为 36 位字符串 |
| 计划子项 | `plan item`，`/system/PlanItem` | `sys_plan_item` | 关联 `plan_id` 与交付物 `module_id` |
| 交付物 | `module`，`/system/module`；Open API 中叫 `deliverable`（`/api/deliverable`、`deliverableId`） | `sys_module` | 后端 i18n `module=交付物`；用例、计划子项通过 `module_id` 关联 |

## 代码仓库

| 业务术语 | 代码标识 / 路由段 | 表名 | 备注 |
|---|---|---|---|
| 代码仓库 | `git repository`，`/system/git/repo`；项目模块段 `code` | `sys_git_repository` | 每项目多个 bare 仓；`slug` 项目内唯一；`disk_path` 为磁盘路径；`visibility` 默认 `project` |

| 合并请求（PR） | `pull request`，`/system/git/repo/{repositoryId}/pulls` | `sys_git_pull_request`、`sys_git_pull_request_comment` | — |
| 发行版 | `release`，`/system/git/repo/{repositoryId}/releases` | `sys_git_release`、`sys_git_release_asset` | — |
| 仓库成员 | `repository member` | `sys_git_repository_member` | 字段 `role` |
| Webhook | `webhook`，`/system/git/repo/{repositoryId}/webhooks` | `sys_git_repository_webhook`、`sys_git_webhook_delivery` | 投递记录含 `event` |
| 关注（收藏）仓库 | `collect` | `sys_user_git_repository` | 字段 `collect` |
