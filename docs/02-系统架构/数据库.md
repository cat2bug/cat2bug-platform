# 数据库

本篇记录支持的数据库、Flyway 迁移约定、核心表清单与测试库约定，改表结构前先看这里。

## 支持的数据库

- **MySQL**：生产推荐；Docker Compose 自带 MySQL 镜像，库名 `cat2bug_platform`。
- **H2**：嵌入式，MySQL 兼容模式（`MODE=MySQL;DATABASE_TO_LOWER=TRUE;CASE_INSENSITIVE_IDENTIFIERS=TRUE`）：
  - 未安装时用内存 H2（`jdbc:h2:mem:cat2bug_platform`）跑 bootstrap 与安装向导；
  - 安装向导可选 H2 或 MySQL，Native 冒烟的 `FRESH=true` 模式即走 H2 安装。
- 业务数据源统一为命名池 `runtime-mysql`（名字带 mysql，但 H2 安装也激活这个池）；`runtime-h2` 仅为旧配置兼容保留。MyBatis 固定使用 `runtime-mysql`，靠 `database-id`（`h2`/`mysql`）区分方言。
- 该池默认 `jdbc.max-size=40`（`application.properties`；安装文件未写这项时用这个默认值）。网页接口、MCP 令牌校验和 MCP 回环进去的接口共用它。MCP 在途回环默认最多用一半。见 [[MCP回环占满数据库连接池导致全站500]]。
- 命名池的 `db-kind` 是**构建期属性**：默认打包为 H2；MySQL 专用包用 `-Dquarkus.profile=mysql` 打包（见 `application.properties` 中 `%mysql.*`），运行期再设 `QUARKUS_PROFILE=prod`。2026-10-14 实测：`deploy/build-embedded.sh` 产出的默认 JAR 连 MySQL 报 "Driver does not support the provided URL"，Docker 镜像因此按 mysql profile 打包、只支持 MySQL，见 [[Quarkus数据源db-kind是构建期属性]]、[[部署]]。Native 同样按默认 H2 打包（`deploy/build-native.sh` 不带 mysql profile）：2026-10-14 实测启动日志含 `jdbc-h2`、`jdbc-mysql` 两个驱动，但业务池 db-kind 为 h2，业务库只支持 H2。归档的 `NATIVE-RELEASE.md` 所说「H2+MySQL 同包」只指两个驱动都打进了二进制。
- 安装后的运行期数据源写入 `config/install/quarkus-runtime.properties`（含凭据，gitignore，勿入库/入文档）。早期生成的该文件为默认数据源格式，与现代码的 `runtime-mysql` 命名池不兼容（登录 500 "Datasource runtime-mysql was deactivated"），需重新安装生成。
- 安装向导判断新库/旧库：库不存在或存在但没有成功的 Flyway 迁移记录 → `new`（执行 Flyway 建表）；已有迁移记录 → `existing`（附着，必要时走 `/upgrade`），实现见 `DatabaseExistenceProbe.probeMysqlMode`、`SetupDatabaseTestService.testMysql`，见 [[安装向导把预建空MySQL库判为existing]]。

## Flyway 迁移

| 项 | 路径 |
|---|---|
| H2 脚本 | `cat2bug-platform-admin/src/main/resources/db/migration/` |
| MySQL 脚本 | `cat2bug-platform-admin/src/main/resources/db/mysql/` |
| 版本表 | `sys_db_version` |

- MySQL 脚本不能放在 `db/migration` 前缀下：Native 下 Flyway 按前缀扫描会把两套脚本混在一起，故独立为 `db/mysql`；`SetupMigrationService.migrationLocation` 按目标库产品名选目录。
- 关键参数（`application.properties`）：`baseline-on-migrate=true`、`baseline-version=0.5.0`、`out-of-order=true`、`migrate-at-start=true`。
- 命名规则：`V{主}_{次}_{修订}[_{序号}]__{英文描述}.sql`，例如 `V0_5_1__init.sql`、`V1_1_0_11__git_repo_webhooks.sql`；版本号与产品版本挂钩，同一版本内用末位序号递增。
- 两套目录脚本数量一致（当前各 41 个），新增迁移必须 H2 与 MySQL 各写一份。
- 最新脚本必须可重复执行（升级测试会删掉最新一条历史再迁移），MySQL 加列见 [[最新迁移脚本须可重复执行-MySQL加列没有IF-NOT-EXISTS]]。
- 升级：已安装实例换包后若有待执行迁移，会走 `/upgrade` 页；Compose 中可设 `CAT2BUG_UPGRADE_SKIP=true` 改为启动期静默迁移。

## 核心表清单

来源：`db/mysql/*.sql` 中的 `CREATE TABLE`。

**组织与权限**
- `sys_user`：用户
- `sys_role`、`sys_user_role`、`sys_role_menu`、`sys_role_dept`：角色及关联
- `sys_menu`：菜单与权限标识
- `sys_dept`、`sys_post`、`sys_user_post`：部门、岗位（岗位菜单已隐藏）
- `sys_team`、`sys_user_team`、`sys_user_team_role`：团队、成员、团队角色
- `sys_member_invite`：成员邀请链接
- `sys_user_config`：用户个人配置

**项目**
- `sys_project`、`sys_user_project`、`sys_user_project_role`：项目、成员、项目角色
- `sys_project_api`：项目 Open API Key 与启用功能
- `sys_module`：项目模块

**缺陷**
- `sys_defect`：缺陷
- `sys_defect_log`：缺陷处理日志（`oper_channel`、`client_name` 记录来源渠道与 MCP 客户端）
- `sys_defect_commit`：缺陷修复关联的代码提交（托管仓库 `repository_id` 或外部 `commit_url`）
- `sys_defect_shard`：缺陷分享
- `sys_user_defect`：用户与缺陷关系（收藏等）
- `sys_project_defect_field`：缺陷自定义字段
- `sys_project_defect_tabs`：缺陷列表页签

**用例与测试计划**
- `sys_case`、`sys_case_prompt`：测试用例及 AI 提示词
- `sys_case_type`：项目用例类型（`enabled` 1 启用 / 0 停用，默认 1；`V1_1_0_46`）
- `sys_case_review`、`sys_case_review_item`：用例评审批次与条目
- `sys_plan`、`sys_plan_item`：测试计划及子项

**文档、报告、评论**
- `sys_document`：项目文档（含 `file_url`、版本）
- `sys_report`、`sys_report_template`、`sys_report_history`：报告、模板、编辑历史
- `sys_comment`：评论/批注
- `sys_user_statistic_template`：统计模板

**Git 代码托管**
- `sys_git_repository`：仓库元数据（`disk_path` 指向 bare 仓）
- `sys_git_repository_member`：仓库成员（read/write/admin）
- `sys_user_git_repository`：用户关注（收藏）仓库
- `sys_git_release`、`sys_git_release_asset`：发行版及附件
- `sys_git_pull_request`、`sys_git_pull_request_comment`：合并请求及评论
- `sys_git_repository_webhook`、`sys_git_webhook_delivery`：Webhook 配置与投递记录

**AI 客户端接入（MCP）**
- `sys_user_access_token`：OAuth 访问 / 刷新令牌（只存哈希，`project_id` 为授权项目；`V1_1_0_42` 起不再有个人令牌）
- `sys_oauth_client`、`sys_oauth_code`：OAuth 动态注册客户端、授权码
- `sys_project_mcp`：项目 MCP 开关与已勾选模块（无记录 = 关闭）
- `sys_mcp_idempotency`：MCP 写操作幂等键（保留 24 小时）

**AI 与集成**
- `sys_robot_agent`、`sys_agent_task`：智能体与任务
- `sys_ai_module_config`、`ai_account`：AI 模型配置与账户
- `im_project_config`、`im_user_config`：第三方 IM（如飞书）配置

**系统与运维**
- `sys_config`、`sys_dict_type`、`sys_dict_data`：参数与字典
- `sys_notice`：公告
- `sys_oper_log`、`sys_logininfor`：操作日志、登录日志（操作日志带 `oper_channel`、`client_name`，网页写 NULL）
- `sys_job`、`sys_job_log`：定时任务及日志
- `qrtz_*`：Quartz 表（原 Spring 线使用；当前后端用 `quarkus-scheduler`，是否仍读写待确认）
- `gen_table`、`gen_table_column`：代码生成器（功能已随 Spring 线移除，表仍由迁移脚本创建）
- `sys_temp_file`、`sys_screen_size`：临时文件、屏幕尺寸
- `sys_db_version`：Flyway 版本表

已删除（迁移中 DROP 且不再创建）：`sys_project_cicd_env`、`sys_project_pipeline*`。旧的 `sys_project_mcp` 在 `V0_6_2_8` 中删除，`V1_1_0_41` 以新结构重新创建（版本更早的删除脚本总是先执行，不会误删）。

## 测试库约定

- Quarkus 测试（`cat2bug-platform-admin/src/test/resources/application.properties`）使用独立 MySQL 库 `cat2bug_platform_test`（`127.0.0.1:3306`，`createDatabaseIfNotExist=true`），Flyway 在 `runtime-mysql` 上启动即迁移，`database-id=mysql`。
- 测试关闭 DevServices，需本机先有 MySQL；不要把测试指向开发/生产库。
