# 部署

本篇汇总 JVM 单 JAR、Docker Compose、Native、rpm 四种部署方式以及持久化要求。后端只有一条线（`cat2bug-platform-admin`），默认 Maven reactor 直接构建，无需 profile；脚本清单见 `deploy/README.md`。

## JVM 单 JAR（推荐）

- 构建：`./deploy/build-embedded.sh`
  - 前端 `npm run build:embedded` → `cat2bug-platform-admin/src/main/resources/META-INF/resources`
  - 后端 `mvn -Pembedded -Prelease -pl cat2bug-platform-admin -am package -DskipTests`
  - 产物统一复制为 `cat2bug-platform-admin/target/cat2bug-admin.jar`（uber-jar）
  - 脚本会先清空 `target/classes/META-INF/resources`，防止旧 hash 前端文件残留进包
- 数据库：该 JAR **只内置 H2 驱动类型**。数据源 `db-kind` 是 Quarkus 构建期属性，需要 MySQL 时按 mysql profile 打包、运行期切回 prod：
  - `mvn -Pembedded -Prelease -Dquarkus.profile=mysql -pl cat2bug-platform-admin -am package -DskipTests`
  - `QUARKUS_PROFILE=prod java -jar cat2bug-platform-admin/target/cat2bug-admin-runner.jar`
  - 用默认 JAR 连 MySQL 会报 "Driver does not support the provided URL"，见 [[Quarkus数据源db-kind是构建期属性]]。
- 运行：`./deploy/run-jar.sh [JAR]`
  - 以 JAR 所在目录为工作目录
  - 自动查找 `config/install/application-install.yml` 与 `quarkus-runtime.properties`（依次找 `./`、JAR 目录、JAR 上级目录），拼入 `QUARKUS_CONFIG_LOCATIONS`；找到安装文件时同时传 `-Dcat2bug.install.config-path`，否则 cd 到 `target/` 后安装状态检测按相对路径找不到安装文件，会误回到 `/setup`
- 开发：`./cat2bug-platform-admin/dev.sh`，或 `mvn -pl cat2bug-platform-admin -am quarkus:dev`
- 首次启动进入安装向导（`/setup/*`）；完成后进程退出，需由 systemd / Docker restart 策略拉起，重启后加载运行期配置。
- 健康检查：`/q/health/ready`。
- 旧版运行期配置不兼容：早期安装生成的 `config/install/quarkus-runtime.properties` 用默认数据源格式，现代码只认命名数据源 `runtime-mysql`，会导致登录 500（"Datasource runtime-mysql was deactivated"）。遇到时重新走一次安装向导生成运行期配置（文件含凭据，勿入库）。

## Docker Compose（仅 MySQL）

- 文件：`deploy/docker/docker-compose.yml`，四个服务：
  - `redis`
  - `mysql`（`mysql-dockerfile`，数据卷 `./mysql-data`；不再 COPY 初始化 SQL，只由 `MYSQL_DATABASE` 预建空库 `cat2bug_platform`，表结构由安装向导执行 Flyway 创建）
  - `web-after`（后端，暴露 2020）
  - `web-front`（nginx，宿主端口 8022）
- 镜像构建前置：`./deploy/docker/build.sh`。它执行前端 `build:prod` 拷到 `deploy/docker/static`，并以 `mvn -Prelease -Dquarkus.profile=mysql -pl cat2bug-platform-admin -am package -DskipTests` 打出单 JAR 拷为 `deploy/docker/cat2bug-admin.jar`；随后 `docker compose build && docker compose up -d`。`SKIP_FRONTEND=true` 只重打后端。
- 后端镜像：`after-dockerfile` 基于 JRE 17，`java -jar cat2bug-admin.jar`，运行期 `QUARKUS_PROFILE=prod`。因 `db-kind` 在构建期固定为 MySQL，**Compose 只支持 MySQL**，安装向导里不要选 H2。
- 卷（三者都必须持久化）：
  - `./uploadPath:/home/uploadPath`：即 `CAT2BUG_PROFILE`（附件、头像、`git/` bare 仓）
  - `./config:/home/config`：安装向导写入的 `install/` 配置（含数据库密码），丢失则重建容器后回到 `/setup`
  - `./mysql-data`：MySQL 数据
- 环境变量：运行期读 `CAT2BUG_*`（`CAT2BUG_IN_DOCKER`、`CAT2BUG_PROFILE`、`CAT2BUG_CACHE_TYPE`、`CAT2BUG_REDIS_HOSTS`、`CAT2BUG_UPGRADE_SKIP` 等）；安装向导的 MySQL 预填仍只认 `SPRING_DATASOURCE_DRUID_MASTER_URL/USERNAME/PASSWORD`——这是安装 YAML 键的历史命名，与运行期框架无关，详见 `deploy/docker/README.md` 与 [[安装向导预检与环境变量预填]]。
- 首次安装：Compose 预建的空库（无成功 Flyway 迁移记录）按 `new` 处理并建表；已有迁移记录的库按 `existing` 附着。此前空库被误判为 `existing` 的问题已修复，见 [[安装向导把预建空MySQL库判为existing]]。
- 已解决：旧版后端默认 `cat2bug.profile=./upload`（容器内即 `/home/upload`）而卷挂在 `/home/uploadPath`，上传与 Git 仓会随容器重建丢失。现在 compose 设 `CAT2BUG_PROFILE=/home/uploadPath` 与卷挂载点一致，"重建后端容器数据仍在"已冒烟验证。
- 数据库密码等写在 compose 文件中，生产部署前必须改掉。

## 邮件（IM 邮件渠道，可选）

- 默认关闭；未配置时启动记一次 INFO「邮件未配置」，邮件渠道静默跳过，其它渠道不受影响。
- 启用时以环境变量（或安装配置）提供，三种部署方式通用：
  - 必填：`CAT2BUG_MAIL_ENABLED=true`、`QUARKUS_MAILER_HOST`、`QUARKUS_MAILER_FROM`
  - 常用：`QUARKUS_MAILER_PORT`、`QUARKUS_MAILER_USERNAME`、`QUARKUS_MAILER_PASSWORD`
  - 加密：隐式 TLS（465）设 `QUARKUS_MAILER_TLS=true`；STARTTLS（587）设 `QUARKUS_MAILER_START_TLS=REQUIRED`
- 账号密码只放运行期环境或私有配置，不写进 `application.properties` 与入库的 compose 文件；Compose 示例见 `deploy/docker/docker-compose.yml` 中的注释（占位符）。规则详见 [[IM多渠道推送]]。

## Native

- 构建：`./deploy/build-native.sh [x86_64|aarch64]`
  - 默认使用 Mandrel 容器构建（`ubi-quarkus-mandrel-builder-image:jdk-21`），跨架构自动加 `--platform`
  - 可选环境变量：`SKIP_EMBEDDED=true`（API-only）、`CONTAINER_BUILD=false`（本机 GraalVM）、`SKIP_UPX=true`
  - 产物：`cat2bug-platform-admin/target/cat2bug-admin-linux-{amd64|arm64}`，UPX 后为同名 `.upx`（默认分发）
- 体积（arm64，2026-10-14 首次交付时）：原始 ELF ≈169 MiB，UPX `--best` 后 ≈38.8 MiB。原定 ~20 MB 目标未达成，产品负责人已接受；amd64 本机未构建过。模块改名后的最新体积见 [[2026-10]]。详见 `openspec/changes/archive/2026-10-14-restore-quarkus-full-delivery/NATIVE-RELEASE.md`。
- 运行：工作目录即数据目录，直接执行二进制，首次进入安装向导（http://host:2020/）。
- 冒烟：`cat2bug-platform-admin/smoke-native-docker.sh [arm64|amd64]`
  - 在 `ubi9/ubi-minimal` 容器中运行 Linux ELF（macOS 不能直接执行），映射 2020，数据目录挂到 `/data`（默认 `/tmp/cat2bug-native-smoke`）
  - 默认模式：复用 Gate A 冒烟的安装配置（默认 `/tmp/cat2bug-smoke/`），把 H2 库与 profile 复制进容器并改写路径
  - `FRESH=true`：空目录走 `/setup/submit`（H2）→ Flyway → 重启
  - 检查项：health → SPA → `/version` → `/login` → 业务接口（含 Excel 导出/导入）
  - `KEEP_CONTAINER=true` 保留容器便于排障；脚本启动前会 `pkill` 本机 `quarkus-run.jar` / `cat2bug-admin-linux` 进程以释放 2020
- Native 适配要点（JJWT 反射、FastExcel 替换 POI、`db/mysql` 独立目录等）见 `NATIVE-RELEASE.md`；运行时初始化特性在 `NativeRuntimeInitFeature`，见 [[Native镜像与操作日志对等]]。
- CI 参考：`deploy/ci/native.yml`（开源项目不维护 CI，仅供自建流水线参考）。

## rpm

- `./deploy/build-native.sh x86_64` 后执行 `./deploy/rpm/cat2bug/build-rpm.sh x86_64`，用 nfpm 把 Native ELF（无 JRE）打成 rpm，产物在 `dist/*.rpm`；`RPM_USE_UPX=true` 改用 `.upx`。配置模板 `deploy/rpm/cat2bug/application.properties`，安装冒烟 `smoke-install.sh`。

## 持久化要求

- 必须持久化整个工作目录（或至少以下全部内容）：
  - `config/install/`：安装配置与运行期配置，含凭据
  - `data/`：H2 数据文件
  - `cat2bug.profile` 指向的目录：上传文件、`download/`、`git/` bare 仓与发行版附件，详见 [[存储与Git仓库]]
- 不能只挂载 `upload` 子目录而漏掉同级的 `git`。
- MySQL 部署另需持久化数据库数据目录（Compose 中为 `./mysql-data`）。
