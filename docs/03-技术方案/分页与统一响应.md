# 分页与统一响应

说明后端列表分页的实现方式（手写 LIMIT/OFFSET + 单独 count）以及 `AjaxResult` / `TableDataInfo` 统一响应与错误码约定；写新接口或前端拦截器时参考。

## 概述

- 不引入 PageHelper（原 Spring 线用 `startPage()`），由 `PageDomain` 计算 `offset/limit`，Mapper 手写 `LIMIT #{limit} OFFSET #{offset}`，并**单独执行 count 查询**，最后 `new TableDataInfo(rows, total)`。字段形态与原 Spring 版兼容，前端无感知。
- 普通接口统一返回 `AjaxResult`（继承 `HashMap`，键 `code` / `msg` / `data`，登录时附 `token`）。

## 关键流程

1. 资源方法接收 `@QueryParam("pageNum")`、`@QueryParam("pageSize")`，连同查询条件交给 Service。
2. Service：`PageDomain.of(pageNum, pageSize)`（为空或小于 1 时分别回落 1 / 10）→ `mapper.countXxx(query)` → `mapper.selectXxx(query, page.getOffset(), page.getPageSize())` → `new TableDataInfo(rows, total)`。示例：`SysPlanService.selectPlanPage`。
3. 需要「全部」时传 `0, Integer.MAX_VALUE`（如 `selectPlanListAll`）。
4. 排序参数见 [[列表排序与注入防护]]，和分页参数在同一查询串里。

### 响应结构与状态码

| 场景 | HTTP 状态 | body |
|---|---|---|
| 成功 | 200 | `AjaxResult` code=200，或 `TableDataInfo`（`total`、`rows`、`code`=200、`msg`=「查询成功」） |
| 未登录 / Token 失效 | 200 | code=401（`SecurityResponses.unauthorized`） |
| 无权限 | 200 | code=403，「没有权限，请联系管理员授权」（`SecurityResponses.forbidden`） |
| 排序参数非法 | 200 | code=500（`PageOrderFilter`） |
| 业务警告 | — | code=601（`AjaxResult.warn`） |
| `ApiException` | 取异常的 `httpStatus`（401/403 例外，仍按上两行返回 200） | code=该状态 |
| 接口不存在 | 404 | 「接口不存在」 |
| 未处理异常 | 500 | 「服务器内部错误」，堆栈只进日志 |

认证/授权失败返回 HTTP 200 + JSON code，是为了与原 Spring `AuthenticationEntryPointImpl` 的行为对齐，让前端 axios 拦截器统一按 `code` 处理。

## 注意事项

- count 与 list 是两条 SQL，WHERE 片段必须共用同一个 `<sql>`/`<include>`，否则 `total` 与 `rows` 不一致。
- `PageDomain` **没有 pageSize 上限**，前端传超大值会一次查全表；如需限制在 Service 层自行裁剪。
- `GlobalExceptionMapper` 对 `CaseImportValidationException` 返回 `AjaxResult.success(校验结果)`，对 `WechatMpNotBindException` 额外带 `sessionKey`，这两类不是普通错误响应。
- 新增接口前端拦截器只认 `code`，不要依赖 HTTP 状态判断登录失效。
