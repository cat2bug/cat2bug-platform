# 列表排序与注入防护

说明列表页「点表头排序」从前端到 SQL `ORDER BY` 的完整链路，以及防止排序参数 SQL 注入的做法；新增可排序列表时照此实现。

## 概述

- 排序参数沿用原 Spring 线（RuoYi 风格）的两个查询参数：`orderByColumn`（列名，驼峰）与 `isAsc`（`ascending` / `descending` / `asc` / `desc`）。
- `ORDER BY` 只能用 MyBatis `${}` 拼接，因此安全性完全依赖**进入资源方法前的字符白名单校验**，Mapper 里不允许直接拼 `${orderByColumn}`。
- 由 `PageOrder`（构造与校验）+ `PageOrderFilter`（拦截非法参数）+ Mapper 中的 `<bind name="_pageOrder">` 模式三件套实现，语义与原 Spring `PageDomain#getOrderBy` + `SqlUtil#escapeOrderBySql` 一致。

## 关键流程

1. **前端**：`Cat2BugTable` 列默认 `sortable="custom"`（服务端排序）；`custom_` / `custom:` 开头的自定义字段列、带 `customFieldKey` 的列一律不可排序。`sort-change` 时页面把 `prop` 写入 `queryParams.orderByColumn`、`order` 写入 `isAsc`，开启 `persistSort` 时排序状态存本地缓存（按 `cacheKey` 区分）。
2. **过滤器**：`PageOrderFilter`（JAX-RS `ContainerRequestFilter`）读取查询参数，调用 `PageOrder.build` 把列名驼峰转下划线、把 `ascending/descending` 归一为 `asc/desc`，再用 `PageOrder.validationError` 校验：
   - 只允许字符 `[a-zA-Z0-9_ ,.]`；
   - 总长度不超过 500。
   不合规则直接 `abortWith`：**HTTP 200 + `AjaxResult` code=500**，消息「参数不符合规范，不能进行查询」或「参数已超过最大限制，不能进行查询」（与原 Spring 抛 `UtilException` 的表现一致）。
3. **Mapper**：查询语句末尾统一写法——
   - `<bind name="_pageOrder" value="@com.cat2bug.framework.web.PageOrder@current()"/>`
   - `<choose>`：`_pageOrder != null` 时 `ORDER BY ${_pageOrder}`，否则走该列表的默认排序（如 `p.create_time DESC`）。
   `PageOrder.current()` 通过 Arc 取当前 Vert.x `RoutingContext` 读参数；无请求上下文、无参数、参数非法、或列以 `custom_` 开头时返回 `null`，即回落默认排序。
4. **别名重载**：当前端列名不是 SELECT 中可直接排序的列时，用 `PageOrder@current('前端列=SQL表达式,...')`，例如缺陷列表 `current('create_member=d.create_by_id')`、文档列表 `current('update_by_name=u.nick_name')`。只替换排序串的**第一个列名**，方向部分保留。

## 注意事项

- 校验是**字符白名单**，不是**列名白名单**：合法字符组成的不存在列名会通过校验，最终表现为 SQL 报错；`isAsc` 非四种标准值时原样透传（同样受字符白名单约束），行为与原 Spring 线一致。
- 新增可排序列表：必须走 `_pageOrder` + `<choose>` 默认排序，不得直接 `${orderByColumn}` / `${isAsc}`。
- 前端列名对应的是 JOIN 表或计算列时，要在 `current('...')` 里补别名，否则会生成 `ORDER BY create_member` 这类在 SELECT 外的列导致报错。
- 缺陷自定义字段存 JSON，不是物理列，前后端都必须忽略 `custom_` 前缀列。
