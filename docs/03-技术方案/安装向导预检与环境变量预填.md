# 安装向导预检与环境变量预填

说明首次安装向导（`/setup`）的后端接口、`GET /setup/preflight` 如何从配置与环境变量推断表单默认值、前端如何合并，以及安装完成后的重启流程；改安装流程、Docker Compose 或 K8s 部署变量时参考。

## 概述

- 未安装时前端进入 `/setup` 向导，选择数据库（H2 / MySQL）、缓存（本地 / Redis）、存储路径、AI（Ollama）后提交。
- `preflight` 让 Docker Compose / K8s 注入的环境变量**自动预填**到向导表单，用户无需重复输入；界面上**不标注**「来自环境变量」。
- 安装状态以磁盘上的安装配置文件为准（默认 `./config/install/application-install.yml`，可由 `cat2bug.install.config-path` 修改）。

## 关键流程

1. **接口**（`SetupResource`，`/setup/**` 属于公开路径，无需登录）：
   - `GET /setup/status`：`installed` / `skipped` / `restartRequired`，并顺带恢复卡住的引导状态；
   - `GET /setup/preflight`：已安装时返回错误；
   - `POST /setup/test/database|redis|ollama|path`：连通性测试；
   - `POST /setup/submit`：写配置、建库迁移，已安装时拒绝。
2. **preflight 推断顺序**（`SetupPreflightService.buildPreflight`，后写覆盖先写）：
   1. 从运行期配置导出安装配置树（`QuarkusInstallConfigExporter.exportFromRuntime`），映射为表单字段：`profile`、`temp`、`logPath`、`aiEnabled`、`aiHost`，MySQL 用户名/密码与 JDBC URL 解析出的 host/port/database，Redis host/port/password/database。
   2. 类型推断：未显式配置数据库类型时，JDBC URL 含 `jdbc:mysql` 推断为 `mysql`，否则保持向导默认 `h2`；未显式配置缓存类型时，有 `spring.redis.host` 推断为 `redis`，否则保持 `local`。
   3. **Docker 运行时**（`CAT2BUG_IN_DOCKER=true` 或存在 `/.dockerenv`）：未显式指定 H2 / 本地缓存时默认 `mysql` + `redis`，并补 Compose 服务名默认值——MySQL host `mysql`（可用 `CAT2BUG_SETUP_MYSQL_HOST` 改）、端口 3306、库名 `cat2bug_platform`（`CAT2BUG_SETUP_MYSQL_DATABASE`），Redis host `redis`（`CAT2BUG_SETUP_REDIS_HOST`）、端口 6379。
   4. **显式环境变量优先级最高**：`SPRING_DATABASE_TYPE`、`CAT2BUG_CACHE_TYPE`、`SPRING_DATASOURCE_DRUID_MASTER_URL`（或 `SPRING_DATASOURCE_URL`）、`SPRING_DATASOURCE_DRUID_MASTER_USERNAME` / `PASSWORD`、`SPRING_REDIS_HOST` / `PORT` 等。`SPRING_*` 前缀是安装配置 YAML 键的历史命名，只用于预填，与运行期框架无关；Spring 后端删除后仍保留，改名需同时改 `SetupPreflightService` 与 `deploy/docker/docker-compose.yml`。
3. **前端合并**（`views/setup/index.vue` 的 `patchFormFromPreflight` / `mergePreflightString`）：逐字段「非空 preflight 值 → 向导硬编码默认值 → 空」；只给了用户名没给密码时，密码保持为空，不编造默认值。
4. **新库/旧库判定**：MySQL 库不存在，或存在但没有成功的 Flyway 迁移记录（如 Docker Compose 用 `MYSQL_DATABASE` 预建的空库）→ `new`，提交时执行 Flyway 建表（与 H2 一致）；已有迁移记录 → `existing`，安装阶段不迁移，schema 落后时安装后进入 `/upgrade`。实现在 `DatabaseExistenceProbe.probeMysqlMode` 与 `SetupDatabaseTestService.testMysql`，测试 `SetupMigrationMysqlTest.emptyExistingDatabaseIsProbedAsNewUntilMigrated`；修复前空库会被判为 `existing` 并报「未检测到表结构」，见 [[安装向导把预建空MySQL库判为existing]]。
5. **安装完成**：写入安装配置与 Quarkus 运行期配置 `config/install/quarkus-runtime.properties`，进程自行退出，需由 systemd / Docker `restart` 策略拉起；前端在「已安装待重启」期间只允许停留在 `/setup` 等待页或 `/login`。
6. **升级预检**：`UpgradeResource` 的 `preflight` 与安装预检复用同一套 JDBC URL 解析，保证两边解析出的 host/port/database 一致。

## 注意事项

- 安装完成前 `/setup/preflight` **无需登录且会回显数据库/Redis 密码**（来自环境变量）；新实例在完成安装前不应暴露在公网。
- 新增可预填字段时，后端 preflight 与前端 `patchFormFromPreflight` 两处同步。
- Native 下 H2 相对路径基准不可靠，写运行期配置时会解析为绝对路径。
- 规格原文以 Spring `Environment` 描述，当前后端通过 `ConfigProvider` + `System.getenv` 实现等价语义。
- Docker Compose 镜像只支持 MySQL（`db-kind` 构建期固定），在容器里选 H2 无法使用，见 [[部署]]。
