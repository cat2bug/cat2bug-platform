# 用例评审纪要模板

说明内置评审纪要 Markdown、占位符与新建项目种子行为。产品决策见进行中的 `case-type-and-review`；编辑器见 [[ADR-019-可视化Markdown统一用Tiptap连续A4纸面]]。

## 内置模板

- 资源：`cat2bug-platform-system/src/main/resources/case-review/default-template.md`
- 栏目参考 GB/T 9386《计算机软件测试文档编制规范》对测试说明类文档的评审信息，以及同行评审纪要常见结构：文档信息 → 目的 → 检查项 → **用例明细表** → 问题与改进 → 结论 → 签字。
- 项目未配置或清空模板时，完成评审仍用该内置文件。
- Native 打包须包含 `case-review/**`（见 `application.properties` / `application-native.properties` 的 `quarkus.native.resources.includes`）。

## 占位符

完成评审时做字符串替换（缺占位符不失败）：

| 占位符 | 含义 |
| --- | --- |
| `{{project}}` | 项目名称 |
| `{{date}}` | 完成当日（`LocalDate`） |
| `{{reviewers}}` | 创建人与完成人去重后用顿号连接 |
| `{{caseCount}}` | 本次用例条数 |
| `{{passedCount}}` / `{{changesCount}}` | 通过 / 需修改条数 |
| `{{cases}}` | 用例明细 **Markdown 表格**（见下） |

## `{{cases}}` 表格

生成形如：

```markdown
| 编号 | 标题 | 类型 | 结论 | 意见 |
| --- | --- | --- | --- | --- |
| 12 | 登录成功 | 功能 | 通过 | 步骤清晰 |
```

- 类型空时写「未分类」；结论为「通过」「需修改」或「待定」。
- 单元格内 `|` 与换行会转义 / 压成空格，避免拆表。

## 新建项目

`SysProjectService` 创建项目时调用 `SysCaseTypeService.seedDefaults`：除预置「功能 / 接口 / 界面」外，若 `case_review_template` 为空，则写入内置模板正文。项目设置页可再改；保存空字符串则落库为 `null`，之后完成评审与 GET 回退到内置。

## 接口

- `GET /system/project/{projectId}/case-review-template`：库中为空时返回内置正文，便于设置页直接看到默认稿。
- `PUT`：空字符串存 `null`（回到内置）。
