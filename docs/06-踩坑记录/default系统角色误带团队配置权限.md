# default 系统角色误带团队配置权限

- 日期：2026-10-27
- 涉及：权限 / 云站 / 角色菜单

## 现象

账号团队角色仅为「普通人员」、项目角色为「测试」时，侧栏仍有「团队设置」，部分团队下还能进「项目设置」。开发、外部人员同样会中招。

## 根因

1. 注册时人人写入 `sys_user_role` → `role_id=10`（`default` / 默认成员）；算权限时系统角色与当前团队/项目角色**始终并集**。
2. 初始化里 `default` 误挂了团队设置、成员管理、改删团队，以及缺陷/用例等业务菜单，并集后覆盖了「普通人员不应有配置权」的预期。
3. 个别成员库里还同时挂了 `team.admin`（界面若只显示一个标签易漏看），会额外带上「项目设置」。

## 解决办法

- 迁移 `V1_1_0_49__trim_default_role_team_admin_menus.sql`：收紧 `default` 菜单，并去掉 `team.default` 上空的「团队设置」父目录。
- 成员管理中确认角色标签；误挂的 `team.admin` 应改为仅普通人员。

## 以后怎么避免

- 改 `default` / `team.default` 菜单时对照 [[权限模型与鉴权链路]]：系统角色只做引导，配置与业务只授给团队/项目管理员类角色。
- 排查「不该有的菜单」时先看 `getInfo.roles` 是否含 `default`、`team.admin`，再查 `sys_role_menu`。
