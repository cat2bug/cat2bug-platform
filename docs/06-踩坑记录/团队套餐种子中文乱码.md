# 团队套餐种子中文乱码

- 日期：2026-11-04
- 涉及：后台 / 部署

## 现象

Admin「团队管理」套餐列与「绑定套餐」下拉显示 `æ™®é€šå›¢é˜Ÿ` 一类乱码，应为「普通团队」。其它业务中文（团队名等）正常。

## 根因

`sys_team_plan` 由 `V1_2_1_1__team_plan_quota` 写入的种子 `plan_name` / `remark`（及表注释）是 UTF-8 字节被按 Windows-1252 误解后再存成 utf8mb4 的双重编码。同批之后的迁移（如 `V1_2_1_7`）中文正常，说明当前 JDBC/Flyway 链路可用；该行是历史错误数据。另：该脚本菜单 ID `2160–2164` 与既有 MCP 等菜单冲突，`WHERE NOT EXISTS (menu_id=…)` 导致套餐维护菜单未插入；菜单文案还误写成「团队角色」，侧栏里几乎找不到维护入口。

## 解决办法

- 新增幂等迁移 `V1_2_1_8__fix_team_plan_mojibake`：用 `CONVERT(UNHEX(...) USING utf8mb4)` 写回正确中文；注释用动态 SQL；菜单改用 `2440+`、名称「团队套餐」，并按 `perms` 去重。
- 前端文案改为「团队套餐」；团队管理页增加「维护套餐」跳转 `/admin/team-plan`。
- 显式 `quarkus.flyway.encoding=UTF-8`。JDBC `characterEncoding` 必须用 Java 名 `utf8`/`UTF-8`（Connector/J 再映射到 MySQL utf8mb4）；写成 `utf8mb4` 会 `Unsupported character encoding` 导致登录 500。

## 以后怎么避免

- 含中文的种子迁移上线后，用 `HEX(列)` 核对是否为正常 UTF-8（如「普」=`E699AE`），不要只看客户端「看起来像中文」。
- 硬编码 `menu_id` 前先查占用；幂等条件优先按 `perms` / 业务键，不要只靠可能冲突的数字 ID。
- 功能名与菜单/i18n 对齐（套餐不要叫角色）；绑定页要能跳到维护页。
- 修已入库乱码时优先 `UNHEX`，少在修复脚本里再塞易被误解码的中文面值。
- 勿把 MySQL 字符集名 `utf8mb4` 填进 JDBC `characterEncoding`。
