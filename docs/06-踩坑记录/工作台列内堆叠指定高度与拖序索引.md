# 工作台列内堆叠：指定高度与拖序索引

- 日期：2026-10-27
- 涉及：后台（工作台 `WorkbenchRows` / `WorkbenchRowEditor` / `row-layout.js`）

## 现象

1. 行设「指定高度」并填了 px，编辑画布高度不变；保存后展示行看起来也不对（内容互相盖住标题，或组件被均分压扁）。
2. 列内把上面的组件拖到下面，顺序不变。

## 根因

1. **编辑器未把 `row.height.px` 写到列容器样式**，只改了数据；展示侧虽设了 `height`，但：
   - flex 子项默认 `min-height: auto` 会把行撑破，需同时锁 `maxHeight` / `overflow`；
   - bare 组件（`.wb-widget.is-bare { overflow: visible }`）会画出盒子盖住兄弟标题；
   - 堆叠列若用 `flex: 1 1 auto`（或错误的 `height: 0` 均分），内容高的组件会抢走高度，矮组件被压扁。指定高度下列内应 **按内容自然堆叠，超出在列上滚动**。
2. **列内移动把落点下标当「插入前」又在 `from < to` 时 `at -= 1`**，上面拖到紧邻下面会变成空操作。落点组件下标应作为 **移动后的最终下标**，不要再减。

## 解决办法

- 编辑：`colsStyle` 按 `fixed` 锁行列高；展示：行/列 `height + maxHeight + overflow`。
- 指定高度 + 堆叠：`flex: 0 0 auto`，列 `overflow: auto`；行高度模式堆叠仍可均分。
- bare 在固定/行高/堆叠列内改为 `overflow: hidden`（或依赖列滚动），标题栏 `flex: 0 0 auto`，正文区可滚。
- `moveWidgetInstance` 同列：`splice` 移除后按目标最终下标插入，禁止「下移再 -1」。

## 以后怎么避免

- 改工作台高度模式时，编辑预览与 `WorkbenchRows` 必须同一套锁高语义，并回归 bare 组件。
- 列内拖序单测至少覆盖「上拖到下标 1 / 下拖到 0」两种，不要只测追加。
