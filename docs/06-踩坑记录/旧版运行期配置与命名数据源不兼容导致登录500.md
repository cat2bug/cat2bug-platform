# 旧版运行期配置与命名数据源不兼容导致登录 500

换新包后能打开页面、登录却报 500 的原因。

- 日期：2026-10-14
- 涉及：后台 / 部署

## 现象

用新构建的单 JAR 启动一个早先安装过的工作目录，页面能打开，登录接口返回 500，日志中有：

```
Datasource runtime-mysql was deactivated
```

## 根因

安装向导写入的 `config/install/quarkus-runtime.properties` 在早期版本中配置的是**默认数据源**（`quarkus.datasource.*`）。现在的代码中业务数据源与 MyBatis 固定使用命名池 `runtime-mysql`，旧文件没有激活这个池，所以第一次查库就失败。

## 解决办法

备份后删除旧的 `config/install/` 运行期配置，重新走一次 `/setup` 安装向导，生成命名池格式的 `quarkus-runtime.properties`（H2 安装同样激活 `runtime-mysql`）。该文件含数据库凭据，不要提交，也不要贴进文档或聊天。

## 以后怎么避免

- 改动安装向导生成的运行期配置格式时，要么提供旧格式迁移，要么在启动期检测旧格式并给出明确提示，而不是在登录时才 500。
- 排查「登录 500」时先看运行期配置是不是旧安装留下的，见 [[数据库]]、[[部署]]。
