# 未选团队/项目的用户会话角色为空

记录登录用户 `user.roles` 为空但菜单权限正常的情况，以及它对按角色判断的逻辑（如数据范围）的影响。

- 日期：2026-10-14
- 涉及：后端 / 权限

## 现象

管理员新建的用户（分配了系统角色、有部门）登录后菜单和接口权限都正常，但按角色数据范围过滤的用户列表一条都查不到。

## 根因

- `SysRoleService.selectRolesByUserId` 依赖 `sys_user_config` 的当前团队 / 项目；用户从未选择过团队或项目时没有这行配置，直接返回空列表，所以会话里的 `user.roles` 为空。
- 这时 `SysPermissionService.getMenuPermission` 走另一条分支，按 `sys_user_role` 直接查菜单权限（`selectMenuPermsByUserId`），所以权限看起来正常。
- 数据范围按 `user.roles` 计算，角色为空就落到「无可用角色 → `d.dept_id = 0`」。

## 解决办法

`SysPermissionService.applyRolesAndPermissions` 在角色为空且不是超级管理员时，把 `user.roles` 设为 `sys_user_role` 中启用的系统角色（`SysRoleService.selectSystemRolesByUserId`），与此时菜单权限的来源保持一致。见 [[权限模型与鉴权链路]]。

## 以后怎么避免

- 任何依赖 `loginUser.getUser().getRoles()` 的新逻辑，都要考虑「没有 `sys_user_config`」这种用户；集成测试里新建的用户默认就是这种状态，正好可以覆盖。
- 不要假设「有权限就一定有角色」：权限集合和角色列表在这条分支上来源不同。
