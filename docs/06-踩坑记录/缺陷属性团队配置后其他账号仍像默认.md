# 缺陷属性团队配置后其他账号仍像默认

- 日期：2026-10-31
- 涉及：后台

## 现象

团队管理员改了「缺陷属性」后，用开发账号登录看新建/列表，仍像未配置的默认字段。

## 根因

1. `loadDefectColumnLayout` 请求失败时把 `enabledBuiltinFieldKeys: null` 写入内存缓存；前端把 `null` 当成「全部启用」，之后同项目不再重拉。
2. 「显示字段」本地缓存键未按用户隔离，同浏览器换账号会串偏好；新建表单一度还跟着这套偏好走。
3. 团队设置页只用 `config.currentTeamId`，可能与当前项目所属团队不一致，改到了别的团队。

## 解决办法

- 布局拉取失败不缓存成「全开」；登出清内存缓存。
- 显示字段缓存键带 userId，并与 Cat2BugTable 的 `cache-key` 对齐。
- 显示字段缓存键必须带 userId；新建/编辑表单顺序可跟个人显示字段序，但键未隔离时仍会串账号（见变更 `defect-form-personal-field-order`）。
- 团队缺陷属性页优先按当前项目的 `teamId` 读写。

## 以后怎么避免

团队级配置入口必须与「当前项目 → teamId」一致；业务读布局失败时禁止回退成「全部默认启用」并锁死缓存。
