# 缺陷更新接口缺字段会重置状态并清空自定义字段

- 日期：2026-10-15
- 涉及：后台 / 缺陷 / MCP 与其它调用方

## 现象

MCP 的 `update_defect` 只传要改的标题，提交后缺陷状态变回「处理中」，自定义字段全部消失。

## 根因

`PUT /system/defect`（`SysDefectService.updateSysDefect`）不是按字段打补丁：请求里没有 `defectState` 时会被当成 0（处理中）写回；`customFields` 反序列化默认是空 map，也会覆盖掉已有的自定义字段值。网页编辑对话框总是提交完整对象，所以一直没暴露。

## 解决办法

调用方先读出缺陷当前的 `defectState`、`customFields`，与要修改的字段一起提交（`McpDefectTools.updateDefect` 即如此）。

## 以后怎么避免

- 任何非网页调用方（MCP、脚本、Open API 封装）改缺陷时都按「读出 → 合并 → 整体提交」处理。
- 若以后把该接口改成按字段更新，需同步检查网页编辑对话框与 MCP。
