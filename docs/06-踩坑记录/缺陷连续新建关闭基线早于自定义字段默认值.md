# 缺陷连续新建关闭基线早于自定义字段默认值

- 日期：2026-10-31
- 涉及：后台（缺陷新建抽屉）

## 现象

勾选「保存本次选项用于下次创建时免填」并保存成功后，表单已重置且未再改内容，点关闭仍提示「有未保存的修改」。

## 根因

1. 连续新建路径在 `reset` 后抓 `defectFormCloseBaseline`。
2. `resetCustomFields` 曾把 `applyCustomFieldDefaults` 放进再一层 `$nextTick`，基线先记下空的 `customFields`，随后默认值写入被当成脏数据。

## 解决办法

- `resetCustomFields` 同步写入默认值后再 `customFieldsEpoch++`。
- 连续新建抓基线再多等一拍 `$nextTick`。
- 关闭序列化将空 `handleBy`（`null`/`[]`）与空描述（`null`/`''`）归一。

## 以后怎么避免

关闭确认的 baseline 必须在所有「重置后的同步/微任务默认值回填」完成之后再 capture；异步补默认值不要放在 baseline 之后。
