# 被引用文件未跟踪导致干净克隆编译失败

本机能编译、干净克隆却编译失败的原因。

- 日期：2026-10-14
- 涉及：后台

## 现象

本机 `mvn install` 一切正常，但从远端干净克隆后编译失败，提示找不到某个类。本次包名改名中遇到的是 `OpenApiKeyResolver.java`（`cat2bug-platform-common/.../common/open/`）：已提交的 `OpenApiKeyResolverImpl` 等代码引用了它，而它在工作区里处于未跟踪状态。

## 根因

本机工作区里有这个文件，编译当然通过；但它没进提交，克隆下来的树里就没有。大批量移动、改名时，新路径上的文件如果不是用 `git mv` 移过去的（例如先复制再删除，或被工具重新生成），就会以「旧路径已删除 + 新路径未跟踪」的形式出现，很容易漏掉 `git add`。

## 解决办法

把该文件补进提交：包名改名提交 `4608c36e` 中，它在新路径 `com/cat2bug/common/open/` 下以新增文件入库（同时删除旧路径）。

## 以后怎么避免

- 提交前看一遍 `git status`，重点检查 `src/main/java` 下的 `??` 未跟踪文件——源码目录里的未跟踪文件几乎都是漏提交。
- 大改名提交后，在临时目录做一次干净克隆或 `git worktree add` 再编译，验证提交本身可构建：

  ```bash
  git worktree add /tmp/c2b-verify HEAD && (cd /tmp/c2b-verify && mvn -o -DskipTests install); git worktree remove /tmp/c2b-verify
  ```
