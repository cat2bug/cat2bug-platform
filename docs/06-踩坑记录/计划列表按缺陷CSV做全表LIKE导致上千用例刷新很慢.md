# 计划列表按缺陷 CSV 做全表 LIKE 导致上千用例刷新很慢

- 日期：2026-10-18
- 涉及：后台

## 现象

项目里某个测试计划挂了五千多条用例后，刷新测试计划列表要等很久。计划条数并不多。

## 根因

列表 SQL 在分页之前，先把**所有**计划子项和**所有**缺陷做一次无法走索引的匹配：

```sql
concat(',', defect_ids, ',') LIKE concat('%,', defect_id, ',%')
```

子项上的 `defect_ids` 是逗号分隔字符串。用例一多，这次匹配接近「子项数 × 缺陷数」，还连带扫整张缺陷日志。外层虽然按项目过滤，过滤发生在统计算完之后。

## 解决办法

统计只扫当前项目（或当前计划）的子项。用例通过数用 `plan_id` 索引做分组。缺陷数先把 CSV 拆成缺陷 ID，再按主键关联，不再和整张缺陷表做 LIKE。

## 以后怎么避免

- 列表接口不要为了几个汇总数去交叉连接大表。
- CSV 外键不能当连接条件；要关联就先拆成 ID，再走主键。

相关：`SysPlanMapper.xml` 的 `selectSysPlanList`、`SysDashboardMapper.xml` 的 `planList`
