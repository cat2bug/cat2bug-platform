# 项目路径键重复更新返回内部错误

- 日期：2026-10-27
- 涉及：后台

## 现象

同一团队下把项目路径名改成已占用的值，前端只提示「服务器内部错误」。

## 根因

`insertSysProject` 已校验 `countByTeamIdAndProjectKey`，但 `updateSysProject` 未校验，直接写库撞唯一索引，异常落到 `GlobalExceptionMapper` 的兜底文案。

## 解决办法

更新时同样规范化并查重（排除自身 `projectId`），冲突抛 `ApiException(400, project.path-key-duplicate)`。团队 `teamKey` 更新对称处理。

## 以后怎么避免

有 DB 唯一约束的字段，写路径（insert/update）都要先业务校验并返回可读 `ApiException`，不要依赖约束异常冒泡成 500。
