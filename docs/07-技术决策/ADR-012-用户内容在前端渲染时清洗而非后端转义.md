# ADR-012 用户内容在前端渲染时清洗而非后端转义

约束以后所有「把用户输入当 HTML 显示」的地方：防 XSS 的责任在前端渲染端，后端保存原文。

- 日期：2026-10-14
- 状态：已采纳

## 背景

原 Spring 线有全局 `XssFilter`，对 `/system/*`、`/monitor/*`、`/tool/*` 的请求参数和 JSON 做 HTML 转义，但通知、评论、报告因为会被转义破坏而被排除在外。Quarkus 后端没有迁移这个过滤器；同时前端 Markdown 渲染开启了 `html: true`，评论、导入结果、通知提醒等十几处直接 `v-html`，缺陷描述里写 `<img onerror>` 会在其他成员的浏览器里执行。依据：`openspec/changes/archive/2026-10-14-close-spring-parity-gaps/design.md`（D1）。

## 候选方案

### 方案 A：恢复后端全局转义

优点：一处生效，覆盖所有入口。

缺点：会把 Markdown、JSON 字段、报告 DSL 里的 `<`、`&` 改掉，存进库的内容不再是原文；Spring 自己就因此排除了通知、评论、报告，等于最危险的几类内容反而不受保护。Open API、导入、Git 等不经过同一过滤链的入口也覆盖不到。

### 方案 B：前端在渲染处统一清洗

优点：后端存原文，Markdown / 报告不受影响；清洗发生在真正把字符串交给浏览器解析的地方，不管数据从哪个入口进来都一样。

缺点：每个 `v-html` 都要记得接清洗函数；新增富文本展示时容易漏。

## 最终决定

采用方案 B：

- 引入 DOMPurify，统一入口 `cat2bug-platform-ui/src/utils/sanitize-html.js`：`sanitizeHtml`（富文本）、`escapeHtml` / `textToHtml`（纯文本当 HTML 显示时）。
- 内联 `style` 只保留白名单 CSS 属性并拦截 `url(`、`expression(` 等值；`target="_blank"` 自动补 `rel="noopener noreferrer"`。
- 评论走 `utils/comment-html.js#commentToHtml`：先转义原文（保留已存在的 HTML 实体），再生成换行和表情标签，最后清洗。
- 图片加载失败不再用内联 `onerror`，改为容器上的捕获阶段 `@error.capture` 监听（`utils/upload-asset.js#handleImageErrorEvent`）。
- 后端不改存储内容，不恢复全局转义。

## 原因

- 清洗必须发生在「字符串变成 DOM」的那一刻才可靠；后端转义既破坏数据又覆盖不全。
- 内容的合法 HTML（Markdown 内联 HTML、报告样式）需要保留，只有渲染端知道哪些标签和属性是需要的。

## 副作用

- 以后新增任何 `v-html`、`innerHTML`、`insertAdjacentHTML`，必须经过 `sanitizeHtml` 或先 `escapeHtml`；代码评审时按此检查。盘点结果见 `openspec/changes/archive/2026-10-14-close-spring-parity-gaps/design.md`「v-html / innerHTML 盘点结果」。
- 报告 / Markdown 中依赖的内联样式如果不在白名单里会被去掉，需要时扩充 `sanitize-html.js` 的属性白名单，而不是绕过清洗。
- 非浏览器消费方（Open API 调用方、导出的 Excel、IM 推送）拿到的是原文，自行负责转义。
