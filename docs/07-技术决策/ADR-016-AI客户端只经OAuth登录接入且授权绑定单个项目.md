# ADR-016 AI 客户端只经 OAuth 账号密码登录接入，一次授权绑定一个项目

约束以后所有「让 AI 客户端访问 cat2bug」的入口：用户只填 MCP 地址，在浏览器用账号密码登录并选团队、项目；凭证只在 MCP 路径生效，且只能操作所选项目。取代 [[ADR-013-AI客户端以个人身份接入-个人令牌加自带OAuth]] 中「个人访问令牌」那一半，OAuth 部分沿用。

- 日期：2026-10-15
- 状态：已采纳

## 背景

ADR-013 上线后，用户反馈两点：一是不想到个人中心生成、复制、粘贴令牌，希望和网页一样用账号密码登录；二是令牌不绑定项目，AI 工具每次都要传 `project` 参数（`团队标识/项目标识` 或项目 ID），用户看不懂「项目引用」是什么，也容易让 AI 误操作别的项目。Cursor、Claude Code、Codex、Claude Desktop 都已支持 MCP 的 OAuth 登录，只填 URL 即可。依据：`openspec/changes/mcp-oauth-project-binding/design.md`。

## 候选方案

### 方案 A：保留个人令牌，令牌创建时选项目

优点：不依赖客户端的 OAuth 支持。

缺点：仍要手动复制令牌；令牌长期有效，泄露面大；两套凭证都要维护。

### 方案 B：只保留 OAuth，令牌不绑定项目，工具继续带 `project` 参数

优点：改动小。

缺点：「项目引用」难懂的问题还在；AI 可在用户所有项目间游走。

### 方案 C：只保留 OAuth，授权页选团队与项目，令牌严格绑定该项目

优点：用户只需登录和选项目；工具不再需要 `project` 参数，AI 不会误操作其他项目；只剩一套凭证。

缺点：要换项目必须重新登录授权；老的个人令牌全部作废。

## 最终决定

采用方案 C：

- 删除个人访问令牌（`c2b_pat_`、个人中心「访问令牌」页、`/system/user/profile/tokens`），迁移 `V1_1_0_42` 删除已有个人令牌和未绑定项目的令牌、授权码。
- 授权确认页 `/oauth/consent` 必须选「团队 → 项目」；只列本人是成员且项目已开启 MCP 的项目（系统管理员与网页一致，可选全部已开启 MCP 的项目）；服务端只接受这个列表里的项目。
- 授权码、访问令牌、刷新令牌都带 `project_id`，刷新时沿用；鉴权时没有 `project_id` 的令牌一律 401。
- MCP 工具不再有 `project` 参数，统一作用于令牌绑定的项目；`list_my_projects` 改为 `get_current_project`。
- 项目设置里 MCP 设置并入「AI 管理」卡片的「MCP 接入」链接，不再单独占一张卡片。

## 原因

- 账号密码登录是用户已有的心智，OAuth 让客户端自己完成换令牌和刷新，用户不碰令牌。
- 授权时就确定项目，权限边界在授权那一刻对用户可见，比每次调用传参数更安全、更好懂。
- 只有一种凭证，鉴权链路和测试都更简单。

## 副作用

- 依赖客户端支持 MCP OAuth；不支持的客户端无法接入（目前主流客户端都支持）。
- 一个 AI 会话只能操作一个项目；多项目场景要在客户端里配多个 MCP 服务或重新登录。
- 用户退出项目或项目关闭 MCP 后，已发令牌调用会被拒（`McpContext.scope` 每次校验），提示重新授权。
- 改动 `OAuthService`、`OAuthResource`、`AccessTokenAuthMechanism`、`McpContext` 时必须跑 `QuarkusOAuthTest`、`QuarkusAccessTokenTest`、`QuarkusMcpServerTest`。
- 链路细节见 [[权限模型与鉴权链路]]、[[MCP接入与权限]]。
