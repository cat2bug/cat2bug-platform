# ADR-017 MCP 使用指南以工具加 Prompt 交付，正文放资源文件，按项目实况拼接

- 日期：2026-10-15
- 状态：已采纳

## 背景

AI 客户端接入 MCP 后只知道工具的一行描述，不了解缺陷流转、角色分工、模块之间的关系，无法在每一步之后引导用户。需要把「系统怎么用」交给 AI，效果类似给它加载一个 Skill。实现见 [[MCP接入与权限]]「使用指南与引导命令」。

## 候选方案

### 方案 A：全部写进初始化说明（instructions）

优点：零代码。

缺点：只在初始化时发一次，客户端常截断或不交给模型；放不下全部模块；无法按项目和用户动态生成。

### 方案 B：MCP Resources

优点：协议里专门用于提供上下文。

缺点：需要 AI 主动读取资源，Cursor 等客户端支持不一致；同样难以带上当前用户的角色与权限。

### 方案 C：指南工具 + Prompts（采纳）

优点：工具所有客户端都支持，调用时能拿到当前用户与授权项目，拼出「本项目实况」；Prompts 在 Cursor、Claude Code 里显示为 `/` 命令，适合固定的引导流程；不支持 Prompts 的客户端仍可用指南工具。

缺点：AI 需要先调用一次工具（靠 instructions 和工具描述提示）；正文与代码规则可能不同步。

## 最终决定

- 指南工具 `get_guide` 按主题返回「本项目实况（代码生成）+ 业务正文（Markdown 资源文件）」，用户无权的模块不展开步骤。
- 引导命令用 MCP Prompts，只生成分步指令，不读写数据。
- 正文放 `cat2bug-platform-admin/src/main/resources/mcp-guide/<语言>/`，不入库、不做网页编辑。

## 原因

- 动态实况让 AI 直接知道「我能做什么、该谁做」，避免让开发去审核这类无效调用。
- 正文放资源文件，改文案不改 Java，也方便审阅。
- Prompts 不做权限判断，实现简单，且不会放大权限（真正的权限仍在工具里，遵守 [[ADR-014-MCP权限为角色权限与项目模块的交集]]）。

## 副作用

- 改缺陷流转规则或默认角色权限时，要同步改 `mcp-guide/zh-CN/defect.md`、`roles.md`；测试只断言关键句。
- 新增资源目录须加入 `quarkus.native.resources.includes`，否则 Native 镜像读不到。
- 目前只有简体中文，以后按语言分目录扩展。
