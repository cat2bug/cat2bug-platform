# ADR-018 移除报告模块且不保留历史数据

记录产品下线报告功能时，对开放接口、库表与历史正文的取舍。

- 日期：2026-10-17
- 状态：已采纳
- 取代：[[ADR-009-报告模版编辑器用Milkdown且DSL为真相源]]

## 背景

项目侧栏的报告（列表、详情、批注、模版、国标预制、Milkdown 编辑器）长期无人使用。继续保留会占用菜单、权限、MCP、IM 通知与三张业务表。产品决定以后不再提供报告。

开放接口 `POST /api/report/defect` 在写入 `sys_report` 的同时创建或更新缺陷。计划表有可空列 `sys_plan.report_id`，无外键。

## 候选方案

### 方案 A：整段删除（页面、接口、表、已有数据）

优点：产品面干净；无只读遗留与「半死」表；后续不必维护模版 DSL / Milkdown。

缺点：已有报告正文、批注、模版永久丢失；JUnit / JLog 若只靠 `/api/report/defect` 推缺陷会失败。

### 方案 B：保留 `/api/report/defect`，只写缺陷不再写报告

优点：外部工具可不改地址。

缺点：仍要维护开放接口契约与部分领域模型；与「系统里不再提供报告」不一致。

### 方案 C：软下线（隐藏菜单，表与接口保留）

优点：可恢复。

缺点：权限、MCP、备份、测试仍会碰到报告；债务不清。

## 最终决定

采用方案 A。

- 删除报告页面、模版编辑器、预制资源、菜单与 `system:report:*`。
- 删除 `POST /api/report/defect`；缺陷仍走既有缺陷接口。
- 新迁移 `V1_1_0_43` 删除 `sys_report`、`sys_report_template`、`sys_report_history`、报告评论行、`sys_plan.report_id`，并从项目 MCP `modules` 去掉 `report`。不改已发布的 `V0_5_1__init.sql`。
- 已有报告数据不导出、不保留。
- [[ADR-009-报告模版编辑器用Milkdown且DSL为真相源]] 被本 ADR 取代。

## 原因

模块无实际用量；报告是生成物而非缺陷 / 用例 / 计划的源数据；保留推送接口会留下与产品定位不符的半套模型。

## 副作用

- 升级后书签 `/…/report` 不再打开报告页。
- 依赖 `/api/report/defect` 的外部工具需改用缺陷接口。
- 代码回滚不能恢复已 `DROP` 的表，须同时恢复升级前的库备份。
- `Cat2BugMarkdown` 仍服务缺陷等编辑；`GET /markdown/{projectId}` 的权限改为缺陷 / 用例 / 计划 / 文档列表权限的或关系。
