# ADR-023 用例类型、评审模板与缺陷属性归属团队

- 日期：2026-10-27
- 状态：已采纳

## 背景

用例类型、评审纪要模板、缺陷属性原按项目隔离，多项目团队需重复配置且易分叉。产品要求这三项成为团队统一配置，仅团队创建人与团队管理员可维护。

## 候选方案

### 方案 A：真·团队级存储 + 项目只消费

优点：单一真相；跨项目口径一致。  
缺点：升级需从源项目迁移并 remap。

### 方案 B：仅入口搬到团队设置，底层仍 per-project

优点：改动小。  
缺点：不解决分叉。

### 方案 C：团队默认 + 项目可覆盖

优点：灵活。  
缺点：实现与心智负担重。

## 最终决定

采用方案 A。管理 API 为 `/system/team/{teamId}/…`；业务读经 `projectId → team_id`。升级时每团队以最早创建的项目为源拷贝配置并按类型名称 remap 用例。

## 原因

与「团队共享质量标准」一致；权限主体与团队管理员角色对齐；避免项目管理员各自改配置造成漂移。

## 副作用

- 项目管理员失去配置写权限。  
- 非源项目上独有类型名在迁移后可能置空，需文档说明。  
- 旧项目设置书签路径失效。
