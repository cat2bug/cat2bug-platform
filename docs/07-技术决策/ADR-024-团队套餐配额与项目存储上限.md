# ADR-024：团队套餐配额与项目存储上限

- 状态：已采纳
- 日期：2026-11-04
- 决策人：产品 / 平台

## 背景

新建项目可按勾选从源项目复制资产（含 Git bare、文档文件），体积可能很大；同时缺少团队人数与项目数量上限，无法约束滥用。需要可管理的「团队套餐」与强制校验点。

## 决策

1. 引入 `sys_team_plan`（Admin 称「团队角色」）：`max_members`、`max_projects`、`max_project_bytes`；种子「普通团队」为 10 / 20 / 5GiB。
2. `sys_team.plan_id` 绑定套餐；新建团队未指定时写入系统默认「普通团队」（`is_system_default=1`，种子 `plan_id=1`）；列默认值亦为 `1`；读路径未绑定时仍回落系统默认。
3. 校验点：加人/邀请接受 → 人数；创建项目 → 项目数；新建复制预估与开跑 → 每项目空间。`sys_project.used_bytes` 在复制完成后更新；日常上传/Git 增长持续计量拦截可二期接同一字段。
4. 云站出站推送的 `cat2bug.cloud.push.max-total-bytes` 与「项目存储上限」相互独立，文案勿混用。

## 后果

- Admin 需维护套餐（不进左侧菜单，从「团队管理 → 维护套餐」进入；可删未绑定套餐，已绑定或系统默认不可删）；团队管理可改绑定。
- 跨团队复制时团队级字典仍按 [[ADR-023-用例类型评审模板与缺陷属性归属团队]] 归属目标团队。
