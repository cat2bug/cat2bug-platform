# ADR-026 团队功能模块闸门优先于角色菜单与项目 MCP

约束团队「页面设置」中的显示模块开关如何与角色菜单、项目 MCP 求交；显示名别名与标识符分离。

- 日期：2026-11-04
- 状态：已采纳

## 背景

团队需要按业务裁剪产品能力（例如只要缺陷、或暂时关掉源码），并把「交付物」等称呼改成团队习惯用语。角色菜单与 [[ADR-014-MCP权限为角色权限与项目模块的交集]] 的项目 MCP 勾选只能收窄个人或 AI，不能在团队层对所有项目一刀切关闭模块，也无法统一改前后端给人看的文案。变更 `team-module-page-settings`。

## 候选方案

### 方案 A：仅前端藏菜单

优点：改动小。

缺点：API / MCP / Open API 仍可调用；无法满足「不管有没有权限都不能用」。

### 方案 B：按项目再做一套模块开关

优点：粒度细。

缺点：与团队统一策略冲突；多项目团队配置成本高。

### 方案 C：团队 `module_page_config` 硬闸门 + 显示名别名

优点：一处配置管全团队；与角色、MCP 求交清晰；别名不改 URL / 权限串 / MCP 键。

缺点：拦截映射表要随权限前缀维护；别名要覆盖前后端文案面。

## 最终决定

采用方案 C：

- 持久化在 `sys_team.module_page_config`（JSON）。开关键：`case_plan`（用例与计划绑死一个开关、两个显示名）、`defect`、`deliverable`、`document`、`code`。允许全部关闭；不级联删业务数据。
- 有效能力 = 角色权限 ∩（MCP 时再 ∩ 项目 MCP 勾选）∩ 团队闸门。`case_plan` off 同时去掉 MCP / API 的 `case` 与 `plan`。
- 团队设置入口与预配置页在模块关闭后仍可进入，以便重新开启。
- 显示名只覆盖给人看的文案（菜单、表单、导出表头、MCP 指南等）；标识符不变。
- 文档上传另有团队 `maxUploadMb`，不得超过系统配置 `sys.upload.maxFileSizeMb`（默认 500）。
- 工作台组件按声明的团队开关键隐藏。

## 原因

硬闸门才能兑现「全项目、全通道不可用」；挂在团队层与缺陷/用例团队配置（[[ADR-023-用例类型评审模板与缺陷属性归属团队]]）一致；不推翻 ADR-014，只在其上加外层求交。

## 副作用

- 权限前缀 → 开关键映射（`TeamModuleGates` 等）须随新业务权限维护。
- 请求权限为 OR 且其中一条未映射到已关闸门时，该接口仍可能放行，需避免给已关模块接口挂无关权限。
- 别名对硬编码中文与 MCP 指南子串替换可能有漏网，首版保证菜单 / 表单 / 导出 / 常见错误。
