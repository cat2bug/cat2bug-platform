## Why

要把 cat2bug 做成「代码质量管理 + AI」平台，开发者的 AI 客户端（Claude Code、Cursor、Codex、OpenCode、Claude Desktop / 网页版）需要能直接读取和操作项目里的缺陷、用例、计划、交付物、文档和代码仓库，形成「AI 读缺陷 → 本地修复 → 回填修复并关联提交 → 测试验证」的闭环。当前平台没有 MCP 服务，客户端无法接入；Open API 是项目级 Key，覆盖面也远小于网页。

## What Changes

- 新增远程 MCP 端点（Streamable HTTP，基于 `quarkus-mcp-server-http`），用个人访问令牌或 OAuth 访问令牌鉴权，并发布受保护资源元数据，未授权时按 MCP 授权规范返回 401。客户端不需要本地代理。
- 新增**项目 MCP 设置**（项目设置 → MCP 页签）：启用开关 + 模块勾选（勾选只是开关，读写由用户角色决定）。
  - 新建项目：自动开启，勾选全部模块。
  - 老项目：没有配置数据，视为**不开启**，需要项目管理员手动打开。
  - 以后新增的模块默认不勾选。
- **权限 = 用户在该项目的角色权限 ∩ 项目已勾选的模块**；只开放项目内模块，系统级操作（用户、角色、部门、菜单、字典、参数、岗位、定时任务、监控、团队管理等）不进入 MCP。
- 工具分两层：
  - **精做工具**：覆盖高频闭环（缺陷全流程含通过 / 驳回、用例、计划、交付物、文档、代码阅读与搜索、我的项目、按 Git 远端地址定位项目）。
  - **通用通道**：`list_operations` / `describe_operation` / `call_operation`，从项目内的网页接口自动生成操作清单，执行时在服务端内部转发到原接口，权限、数据范围、日志与网页完全一致。
- **修复回填关联提交**：修复缺陷时可附提交列表；托管在 cat2bug 的仓库校验提交存在，外部仓库只记录提交号与链接；缺陷详情展示关联提交。
- **来源审计**：经 MCP 的操作在操作日志与缺陷日志中标明「经由 MCP」和客户端名称。
- 文档：新增各客户端接入说明（Cursor、Claude Code、Codex、OpenCode 用请求头；Claude Desktop / 网页版用 OAuth）。

## Capabilities

### New Capabilities

- `project-mcp-settings`：项目级 MCP 开关与模块勾选、默认值规则、模块与权限前缀的映射。
- `mcp-endpoint`：MCP 端点、令牌鉴权、受保护资源元数据、按项目计算有效权限、来源审计。
- `mcp-tools`：精做工具集与通用通道的行为、项目定位方式、写操作的幂等与工具注解。
- `defect-commit-link`：缺陷修复关联提交的存储、校验与展示。

### Modified Capabilities

（无。缺陷流转、操作日志的既有规范未单独建档，相关行为在新能力中描述。）

## Impact

- 前置依赖：`upgrade-quarkus-lts`（MCP 扩展要求 Quarkus 3.27）与 `personal-access-token-oauth`（令牌与 OAuth）。
- 数据库：新增项目 MCP 设置表、缺陷提交关联表；操作日志与缺陷日志新增来源与客户端字段（H2 与 MySQL 两套脚本）。
- 后端：admin 新增 MCP 工具类与通用通道；system 新增按（用户，项目）计算权限而不改动用户当前项目的服务；项目创建时写入默认 MCP 设置；缺陷修复接口支持提交列表。
- 前端：项目设置新增 MCP 页签；缺陷详情显示关联提交；日志显示「经由 MCP」标记；七种语言词条。
- 安全：AI 可执行写操作，需要确认权限求交集在所有入口一致生效，并做安全审查。
- 交付：Native 构建需包含 MCP 扩展；冒烟脚本增加 MCP 调用检查。
