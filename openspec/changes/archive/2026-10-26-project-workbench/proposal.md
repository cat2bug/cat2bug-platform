## Why

项目落地页「仪表盘」是固定统计墙：全员同一布局、以看数为主、不能在页内闭环处理缺陷/计划项。用户需要的是项目内「工作台」——待办优先、可在台面完成大部分日常操作，且每人可按角色预设与显隐排序定制内容；原统计能力拆成可开关组件，而非整页不可拆的死布局。

## What Changes

- 菜单与落地页叙事从「仪表盘」改为「工作台」（一期路由段仍为 `dashboard`，避免分享链接 / MCP 模块键大改；二期可评估别名 `workbench`）。
- **一期（方案 A+C+D）**：
  - **A**：轻定制——组件显隐 + 上下排序；配置按「用户 × 项目」服务端持久化。
  - **C**：角色预设（测试 / 开发 / 管理 / 空白）一键套用，可再微调。
  - **D**：页顶双页签「工作台 | 看板」；看板侧为原统计墙拆成的**可开关组件**（非整页不可拆死布局），与工作台共用同一套布局配置模型。
  - 待办类组件支持台面内快捷操作（缺陷流转、计划项通过/失败等），复用现有详情抽屉 / 弹层，不嵌整页。
  - 工作台含**个人统计图表**（我的 KPI、我的处理趋势、名下状态分布等）；看板保留**项目级**统计，二者视角分离。
- **二期（方案 B）**：自由栅格（位置 + 尺寸），在一期组件与配置模型上升级，不推翻一期数据。
- 效果图 / 交互预览随任务产出（`openspec/changes/project-workbench/preview/`），实现前确认视觉与信息架构。
- 不引入跨项目总览工作台（一期范围：仅项目内）。

## Capabilities

### New Capabilities

- `project-workbench`: 项目内工作台落地体验——页签（工作台/看板）、角色预设、组件显隐与排序、用户×项目布局配置、一期组件目录与台面内操作边界；二期栅格扩展约定。

### Modified Capabilities

- `project-path-route`: 分享链接 / 空路径落地语义改为打开项目**工作台**（路由仍解析到既有 dashboard 模块路径）。
- `project-scoped-module-routes`: 模块 `dashboard` 的 UI 呈现为工作台；空模块与 `/dashboard` 行为与工作台一致；菜单文案与 i18n 对齐。

## Impact

- 前端：`cat2bug-platform-ui/src/views/system/dashboard/` 重构为工作台壳 + 组件注册表；菜单 / i18n「仪表盘」→「工作台」；布局编辑与预设 UI。
- 后端：新增（或扩展）用户×项目工作台布局读写 API；复用现有 `/system/dashboard/*`、缺陷/计划/用例等业务 API；可借鉴 `sys_user_statistic_template` 的 JSON 配置模式。
- 权限：沿用 `system:dashboard:query` 与各业务权限；组件仅展示用户有权访问的数据与操作。
- MCP / 模块键：一期保持 `dashboard`；指南文案可称工作台。
- 文档：实现后回写 `docs/01-产品需求/产品定位与核心功能.md` 仪表盘条目；无需新 ADR（未推翻既有 ADR）。
