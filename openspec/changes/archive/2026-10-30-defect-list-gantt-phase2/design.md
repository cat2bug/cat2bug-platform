## Context

一期 `defect-list-gantt-view` 已落地自研甘特：左列表 + 右时间轴、未排期池、处理人/交付物分组、单条拖拽写回 `planStartTime` / `planEndTime` / `handleBy` / `moduleId`。缺陷实体尚无计划依赖与基线字段；库中无对应边表/快照表。一期明确不做依赖线、关键路径、资源负荷、基线、框选批量，并否决 GPL/商用整库甘特。

二期在同一壳上扩展上述五项；协议与产品约束不变：继续自研，不引入 dhtmlx/Bryntum 等。

## Goals / Non-Goals

**Goals:**

- 项目内缺陷计划依赖（默认 FS）可 CRUD，甘特绘制连线。
- 当前筛选结果集上计算并高亮关键路径。
- 按处理人展示可见窗口资源负荷，过载可识别。
- 可冻结/查看/对比计划基线（相对当前计划起止）。
- 时间轴框选多条后批量平移改期（权限同编辑）。
- 与一期视图切换、页签筛选、分组偏好兼容。

**Non-Goals:**

- 引入 GPL/商用整库甘特或重写一期壳。
- 里程碑专用实体、空白拖新建、自动调资源平衡、SS/FF/SF 全类型依赖（一期依赖仅 FS；其它类型可后续扩展）。
- 跨项目依赖。
- 强制改期时自动推移后继（可提示冲突，默认不自动级联，除非实现时产品确认开启「推移后继」开关——本设计默认**仅提示**）。

## Decisions

1. **继续自研，不换库**  
   - 在现有 SVG/DOM 时间轴上叠加依赖层、框选层、基线幽灵条与负荷条带。  
   - 备选否决：Bryntum（商用）、dhtmlx 免费版（GPL）。若未来换库须单开 ADR。

2. **依赖持久化：项目内有向边表**  
   - 新表（示意）`sys_defect_plan_link`：`project_id`, `from_defect_id`, `to_defect_id`, `link_type`（一期仅 `FS`）, 唯一 `(from, to, type)`，禁止自环；写时校验两端同属该项目。  
   - API：`GET/POST/DELETE /system/defect/plan-link`（或挂在 project 下）；列表可随甘特结果集附带「当前可见缺陷相关边」。  
   - 甘特交互：开依赖层后悬停条显示左右连接点；**尾→头**或**头→尾**拖拽创建 FS；依赖用虚线绘制；点选虚线后 `Delete` 删除。  
   - 备选：塞进缺陷 JSON 字段——否决（难查、难校验环）。

3. **关键路径：按计划日期推断的最长链（与手动依赖解耦）**  
   - 输入：当前筛选结果集中已排期缺陷的 `planStartTime` / `planEndTime`（不要求用户先建依赖边）。  
   - 推断衔接：前置结束日的次日 ≤ 后继开始日则可连；在该图上取**一条**代表性最长工期链高亮（同日并列只留链上一个点），非关键条淡化；**不画连线/箭头**（连线留给依赖层）。  
   - 「依赖层」仅画用户声明的依赖；二者视觉独立。大数据量仍受甘特 `pageSize` 约束。

4. **资源负荷：处理人 × 时间窗聚合**  
   - 仅「按处理人」分组时展示更自然；交付物模式下可隐藏或按条上处理人仍聚合。  
   - 指标：可见轴范围内每人每天占用条数（或人天），超过阈值（本地默认，如 1 条/天或可配置阈值）标警示。  
   - 一期不做「跨项目共享池」与精确工时字段；占用按计划日期区间展开。

5. **基线：每项目一份「当前基线」快照（可再扩展多版本）**  
   - 表（示意）`sys_defect_plan_baseline` + `sys_defect_plan_baseline_item`（`defect_id`, `plan_start`, `plan_end`），或单表 JSON 批次。二期默认：**每个项目同时只有一个活跃基线**（再次冻结覆盖或显式「另存」——实现选覆盖+确认）。  
   - 甘特叠加半透明基线条；与当前计划起止不同则偏移可见。  
   - 权限：冻结/清除需 `system:defect:edit`（或项目管理权限，实现与菜单对齐）。

6. **框选批量：轴上矩形选 → 批量平移**  
   - 模式开关或修饰键（design 推荐：工具条「框选」+ 拖矩形；避免与条拖冲突）。  
   - 批量操作一期范围：**统一平移 N 天**（保持各自时长）；不强制批量改处理人/交付物（可列后续）。  
   - 写回：串行或批量 update 现有缺陷接口；汇总成功/失败。依赖冲突：批量后对选中集做一次 FS 校验提示。

7. **ADR**  
   - 自研扩展仍属产品实现选择；**拟不新增 ADR**，除非依赖/基线模型被其它模块强依赖。归档前再评估。

## Risks / Trade-offs

- [筛选截断导致关键路径不完整] → 文案标明「基于当前列表」；必要时提高甘特 pageSize 或提示筛选。  
- [依赖环] → 写入拒绝并提示。  
- [框选与条拖手势冲突] → 独立框选模式；退出模式恢复单条拖。  
- [基线覆盖误操作] → 冻结前确认；可查看冻结时间。  
- [负荷仅近似] → 文档写明按计划区间非实际工时。  
- [多人镜像行与依赖线] → 连线锚到 `defectId` 的主几何（同 defect 多行时连到首次出现行或处理人主行，实现选定一种并测）。

## Migration Plan

1. Flyway 增加依赖边表与基线表（空表可上线）。  
2. 后端 CRUD + 权限；前端甘特叠加层分开关渐进（依赖线 → 关键路径 → 基线 → 负荷 → 框选）。  
3. 回滚：关 UI 开关并停写 API；表可保留。

## Open Questions

- 批量平移是否提供「同时推移后继」开关（默认关）。  
- 基线是否需要命名多版本（二期默认单活跃基线）。
