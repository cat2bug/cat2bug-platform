## ADDED Requirements

### Requirement: 缺陷列表提供看板视图入口

缺陷页内容视图切换 MUST 在「甘特」之后提供「看板」选项，与表格 / Excel / 甘特同级。选中看板时 MUST 渲染看板组件并共用父级当前筛选与页签范围。视图偏好 MUST 写入既有本地键白名单（扩展允许值包含看板组件名）。

#### Scenario: 从甘特旁切换到看板

- **WHEN** 用户在缺陷页点击视图切换中的「看板」
- **THEN** 主内容区显示三泳道看板，且列表数据范围与切换前筛选条件一致

#### Scenario: 刷新后记住看板

- **WHEN** 用户上次将内容视图设为看板并再次进入缺陷页
- **THEN** 默认仍为看板视图（在本地偏好有效且白名单包含该值时）

### Requirement: 三泳道按状态分桶

看板 MUST 固定三列泳道，文案为「处理中」「待验证」「已结束」：

- 处理中：状态名为 `PROCESSING` 或 `REJECTED` 的缺陷；`REJECTED` MUST 有可区分的视觉标记
- 待验证：`AUDIT`
- 已结束：`CLOSED`

处理中列内 MUST NOT 提供将 `PROCESSING` 与 `REJECTED` 互相拖换的交互。`RESOLVED` MUST NOT 作为可拖拽卡片进入上述三列。

#### Scenario: 已驳回出现在处理中列

- **WHEN** 当前筛选结果含状态为已驳回的缺陷
- **THEN** 该卡片出现在「处理中」泳道并带已驳回标记

#### Scenario: 列内不互拖处理中与已驳回

- **WHEN** 用户在处理中列内拖动一张处理中卡片到另一张已驳回卡片位置
- **THEN** 系统不改变任一缺陷状态（可仅忽略或恢复原视觉位置）

### Requirement: 跨泳道拖拽映射既有流转动作

跨泳道松手 MUST 映射为既有流转动作，并调用对应单条 API（多选时对选中集合串行调用），MUST NOT 通过通用更新接口直接改写 `defectState`：

- 处理中 → 待验证：`repair`
- 待验证 → 处理中：`reject`
- 处理中 → 已结束：`close`
- 待验证 → 已结束：若选中每一条对当前用户均满足「通过」可见性则 `pass`；否则若每一条均满足「关闭」可见性则 `close`；否则 MUST 拒绝落点并提示
- 已结束 → 处理中：`open`

动作是否允许 MUST 与表格行内按钮使用同一套可见性规则（权限码与创建人/处理人身份）。

#### Scenario: 处理人将处理中拖到待验证

- **WHEN** 当前用户是该缺陷处理人、具备修复权限，并将处理中卡片拖入待验证泳道且在弹框中选定审核人后确认
- **THEN** 系统调用修复接口成功，卡片出现在待验证列

#### Scenario: 待验证优先走通过

- **WHEN** 当前用户是待验证缺陷的处理人且具备通过权限，将该卡拖入已结束
- **THEN** 系统走通过动作（描述按现有通过规则可选），成功后卡片在已结束列

#### Scenario: 无通过资格时关闭进入已结束

- **WHEN** 用户不具备对该待验证缺陷的通过资格，但具备关闭权限，并将其拖入已结束且填写必填关闭描述后确认
- **THEN** 系统走关闭动作，成功后卡片在已结束列

#### Scenario: 无权限拒绝落点

- **WHEN** 用户对某卡既不能通过也不能关闭，试图拖入已结束
- **THEN** 卡片回到原泳道，且不调用流转接口

#### Scenario: 重开拖回处理中

- **WHEN** 用户具备重开权限，将已结束卡片拖入处理中并填写必填描述后确认
- **THEN** 系统调用重开接口，卡片出现在处理中列且状态为处理中

### Requirement: 需要输入时松手后弹框

当映射动作按现有单条/批量规则需要必填人员或必填描述时，松手后 MUST 先打开对应弹框；用户取消 MUST NOT 调用流转接口，卡片 MUST 留在原泳道。字段必填规则 MUST 与现有 DefectTools / 批量弹框一致。

#### Scenario: 驳回取消不改态

- **WHEN** 用户将待验证卡片拖入处理中后打开驳回弹框并取消
- **THEN** 缺陷状态保持待验证，卡片仍在待验证列

#### Scenario: 修复缺少审核人不可提交

- **WHEN** 用户拖入待验证触发修复弹框且未选择审核人
- **THEN** 提交被校验拦截，不得调用修复接口

### Requirement: 多选同时拖动

看板 MUST 支持多选卡片并整组拖向目标泳道。仅当选中集合能映射为同一动作且每一条对该动作均满足可见性时 MUST 允许落点；否则 MUST 整组回弹且不调用接口。提交时 MUST 串行调用单条流转 API（或复用与批量操作相同的串行提交模式）。

#### Scenario: 多选修复全部为处理人

- **WHEN** 用户多选多条自己为处理人的处理中缺陷并拖入待验证，在弹框确认审核人后提交
- **THEN** 每条均被调用修复接口，成功者进入待验证列

#### Scenario: 多选中混入不可修复项

- **WHEN** 用户多选集合中至少一条对当前用户不可修复，并拖向待验证
- **THEN** 整组回弹，不调用任何修复接口

### Requirement: 看板提供指派入口

看板 MUST 为单卡提供指派入口（菜单或等价控件），打开与表格相同的指派弹框；态 MUST NOT 因指派而改变。多选时 MUST 能对选中集合发起批量指派（严格每一条均可指派时），复用现有批量指派字段与串行提交行为。

#### Scenario: 单卡指派换人

- **WHEN** 用户对处理中卡片选择指派并选定新处理人后确认
- **THEN** 系统调用指派接口，卡片仍在处理中列且处理人已更新

#### Scenario: 多选指派严格求交

- **WHEN** 用户多选中含有自己不可指派的缺陷
- **THEN** 批量指派入口不可用或落点/提交被拒绝，不得对不合格项调用指派接口
