## Context

团队缺陷属性管理页（`views/system/team/option/defect-fields/index.vue`，路由 `/team-options/team-defect-fields`）一次拉取团队全量字段目录后本地排序与分页。列表含「来源」（系统/自定义）、「属性键」、「显示名称」等列，字段多时靠翻页定位成本高。页顶仅有「新增属性」，未按列表页工具条左过滤 / 右动作布局。

目录归属、权限与项目只读消费由既有 `defect-field-catalog` 与 ADR-023 约束；本变更只增强管理列表的客户端筛选体验。

## Goals / Non-Goals

**Goals:**

- 工具条左侧提供来源下拉 + 属性名模糊输入；右侧保留「新增属性」。
- 属性名同时对 `fieldKey` 与显示名称（含内置字段解析后的展示文案）做不区分大小写的子串匹配。
- 来源为精确枚举过滤：全部 / 系统 / 自定义。
- 过滤后分页 `total` 与页数据正确；改条件重置到第 1 页。
- 对齐 `docs/04-UI规范/组件与交互约定.md` 列表页工具条（改值即查、控件带前缀图标、无「查询」按钮）。

**Non-Goals:**

- 不新增或修改后端 list 查询参数、索引或分页协议。
- 不改字段 CRUD、启用开关、排序持久化语义（`sortOrder` 仍写全量目录）。
- 不改造为 `Cat2BugTable`（可后续增量）；本变更只加过滤与工具条结构。
- 不做筛选条件本地持久化。

## Decisions

### 1. 前端过滤，不改 API

- **选择**：在已有 `fieldList` 上 `filter`，再切片分页。
- **替代**：服务端 `source` / `keyword` 参数——字段量级通常几十条，不值得动契约与权限边界。
- **理由**：与现状全量拉取一致，改动面最小。

### 2. 属性名 = 键 ∪ 显示名

- **选择**：关键字 trim 后，对 `fieldKey` 与 `_displayLabel` / `displayFieldLabel(row)` 做 `includes`（大小写不敏感）。
- **替代**：只搜键或只搜显示名——已否决；用户确认方案 C。
- **空关键字**：不按名称过滤。

### 3. 来源用下拉精确筛

- **选择**：`'' | 'system' | 'custom'`（或等价），映射现有 `isBuiltinField(row)`。
- **替代**：对来源文案做模糊输入——两档枚举体验差，已否决。
- **「全部」**：不按来源过滤。

### 4. 工具条布局

- **选择**：`.list-page-toolbar` + `__filters` / `__actions`；「新增属性」用 `type="primary" plain` + `cat2bug-btn-outline`（与用例类型等一致）。
- **替代**：保留现有 `defect-field-tools` 仅左侧塞输入——不符合 UI 规范。

### 5. 过滤态下的改序

- **选择**：上下箭头仍对**全量** `fieldList` 按行真实邻居改序并落库；过滤只影响可见行。可见行的「能否上/下移」仍按全量索引判断（过滤后相邻两行在全量中未必相邻，箭头可能看起来「跳过了看不见的字段」——可接受）。
- **替代**：过滤时禁用改序——更安全但限制操作；首期不采用。
- **理由**：避免过滤态改序写错相对位置；文档在风险里注明体感。

### 6. 空结果

- **选择**：空表 + 分页区按 `total === 0` 隐藏或显示「共 0 条」（与现有 `v-show="total > 0"` 一致即可）。
- **不**单独挂 `Cat2BugEmpty` 插画（管理列表筛选空态保持轻量）。

## Risks / Trade-offs

- [过滤后改序体感跳格] → 文档说明按全量邻居移动；若用户反馈再禁过滤态改序。
- [内置显示名依赖 i18n] → 匹配用当前语言解析后的显示文案；切换语言后需以新文案搜索（列表本就会随 locale 重算展示）。
- [字段上千时全量拉+滤变慢] → 当前产品规模可接受；若膨胀再开服务端筛选增量。

## Migration Plan

- 纯前端发布；无 DB / 权限迁移。
- 回滚：还原该页工具条与 filter computed 即可。
