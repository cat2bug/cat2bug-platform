## Context

新建项目（`add.vue` → `POST /system/project` → `SysProjectService.insertSysProject`）目前只写项目行、创建人角色与默认 MCP，不创建模块/用例/文档/Git。项目设置 hub 四卡中「项目信息」承载身份与生命周期；其余为成员、AI、第三方。工作日历不属于项目配置，不进入复制范围。平台已有出站推送勾选与体积估算（`ProjectCloudPushService.estimate`），但无「导入为新项目」。Admin「系统」有团队/项目列表与锁定，无人数/项目数/存储配额。

约束：不推翻 ADR-023（用例类型/缺陷属性归属团队）；Git bare 与文档正文依赖磁盘（见存储与 Git 相关文档）；复制体积受「每项目最大空间」约束。

## Goals / Non-Goals

**Goals:**

- 新建时可从符合权限的源项目按勾选复制资产与配置，并展示预估占用 vs 项目空间上限。
- Admin 可维护团队角色（套餐），默认「普通团队」（人数 10 / 项目 20 / 每项目空间 1G），团队绑定后在加人、建项目、复制灌入时强制校验。
- 跨团队源项目允许；成员与角色可复制；大体积异步灌入。

**Non-Goals:**

- 不复制缺陷、测试计划、API Key、出站推送、项目信息卡字段、个人缺陷页签/工作台布局。
- 一期不把「日常上传/Git 增长」做成完整配额计量账单（须预留已用空间口径；复制与创建先卡上限，日常增长可二期持续计量拦截）。
- 不新建独立 Admin 登录体系（沿用系统超级管理员 `admin`）。
- 不实现「从云站推送包还原为项目」。

## Decisions

### D1. 创建与复制两阶段

- **选择**：先按现有路径创建空项目（含创建人），再启动 `ProjectCopyJob`（或等价异步任务）按勾选灌入；创建接口立即返回 `projectId` + `copyJobId`（若开启复制）。
- **理由**：与现有 `insertSysProject` 事务边界清晰；Git/文档拷贝耗时长，不宜堵在同步 HTTP。
- **备选**：单请求同步复制 — 拒绝，超时与锁风险高。

### D2. 源项目候选与鉴权

- **选择**：列表 API 返回「当前用户为成员且角色含 `project.create-by` 或 `project.admin`」的项目（可跨团队）；复制执行时再次校验同一条件，防止越权。
- **理由**：与产品约定及现有 `ProjectPlanAuth` 口径一致。

### D3. 勾选模型与依赖

| 勾选块 | 行为 |
|--------|------|
| 源码 | 多选仓库；复制元数据 + **整个 bare 目录**到新 `teamKey/projectKey/slug`；一期不复制 PR/Release/Webhook（可在 design 备注为后续） |
| 交付物 | 全部或所选 `sys_module`（补祖先），ID remap；UI 为 Tab 内全选/搜索/单选 |
| 用例 | 全部或所选 `sys_case`；**若勾选用例且未勾交付物，自动带交付物**（全选或按用例 module + 祖先） |
| 文档 | 全部或所选文档（补祖先）；UI 同 Tab 模式 |
| 源码 | 所选 slug 列表（原多选，现纳入 Tab） |
| 文档 | 整棵文档树 + **磁盘文件** |
| 成员 | 复制源项目成员及项目角色到新项目；创建人仍保留创建人角色；冲突时以目标侧创建人角色为准 |
| AI / IM | 按项目配置表复制；密钥类字段按现有脱敏/再配置策略（能拷则拷，OAuth 令牌不可用则置空并提示）；工作日历不复制 |

排除：信息卡（名称/Key/简介/图标/API/推送/删除）。

### D4. 跨团队与 ADR-023

- **选择**：用例的 `case_type` 等外键映射到**目标团队**已有类型（按名称/编码匹配）；无匹配则落入目标团队默认类型或留空（实现时选一种并在任务中写死）；**不**把源团队类型字典写入目标团队。
- **理由**：遵守 ADR-023。

### D5. 体积估算与项目空间

- **选择**：复用/抽取推送估算逻辑，对勾选块求和（Git=`directorySize`，文档=`Files.size`，用例/模块附件计文件，配置按 JSON 小计）；与目标团队套餐的 `maxProjectBytes`（默认 1GiB）比较。超限：禁止提交创建复制，或禁用继续勾选并提示。
- **已用空间**：新项目复制完成后写入/更新「项目已用字节」；日常计量二期可接同一字段。一期至少在复制前后校验「预估 ≤ 上限」且「复制后实占 ≤ 上限」。

### D6. Admin 团队角色数据模型

- **选择**：
  - `sys_team_plan`（或 `sys_team_role_plan`）：id、名称、`max_members`、`max_projects`、`max_project_bytes`、是否系统默认、排序等。
  - 种子：`普通团队`（10 / 20 / 1073741824）。
  - `sys_team.plan_id`（或关联表）绑定套餐；无绑定时回落到系统默认「普通团队」。
- **校验点**：邀请/加人 → `max_members`；`insertSysProject` → `max_projects`；复制估算/完成 → `max_project_bytes`。
- **UI**：Admin 侧栏「系统」下左下新增「团队角色」；仅 `admin` / `*:*:*`；团队管理页可改绑定套餐。

### D7. 前端交互

- 新建页开关展开：源项目下拉 + 勾选块（源码子列表、配置子项）+ 占用条「已选约 x / 上限 y」。
- 创建成功后：若有 copy Job，跳转项目并展示进度（可借鉴出站推送进度组件模式）。

## Risks / Trade-offs

- [跨团队类型/字段不一致] → 按 D4 映射；规格写明不匹配时的行为。
- [Git/文档磁盘拷贝失败半成品] → Job 可失败回滚策略：项目保留，失败块可重试或标记；不自动删项目。
- [成员复制带来多余权限] → 仅复制项目角色；跨团队用户必须已是平台用户且可进目标团队（若源成员不在目标团队，先加入团队或跳过并记日志——**建议：不在目标团队则自动按团队名额尝试加入，超员则跳过该成员**）。
- [空间计量不准] → 一期以复制估算+实占为主；日常增长二期。
- [与出站推送上限混淆] → 文案区分「云站推送上限」与「项目存储上限」。

## Migration Plan

1. Flyway：建套餐表、团队绑定列、项目已用字节列（或独立计量表）；插入默认「普通团队」；已有团队绑定默认套餐。
2. 发布后端配额校验 + Admin API/UI。
3. 发布新建复制 UI 与 Job。
4. 回滚：关闭复制开关特性（配置 flag）仍可建空项目；套餐表保留不影响旧逻辑若校验可关。

## Open Questions

- 源成员不在目标团队时：自动入团 vs 跳过（design 建议自动入团，超员跳过）——实现前可再确认。
- Git 是否一期带 PR/Webhook：默认**不带**。
- 日常附件/Git 增长是否在本变更内做软拦截：默认**只做复制与创建校验**，计量字段预留。
