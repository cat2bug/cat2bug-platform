## Why

新建项目目前只能得到空壳（项目行 + 创建人 + 默认 MCP），同构项目要手工重建交付物、用例、文档、源码仓与设置，成本高。同时平台缺少团队人数、项目数与项目存储上限，无法约束滥用与复制体积。需要一次交付「按勾选从源项目复制」与「Admin 团队套餐配额」两块能力。

## What Changes

- 新建项目页增加「复制项目配置」开关：选择源项目后，可勾选源码仓（多选，含 bare 磁盘）、全部测试用例、全部交付物树、全部文档（含文件）、以及设置页除「项目信息」卡以外的配置（含成员与角色、AI、第三方 IM）。工作日历不属于项目配置，不纳入复制。
- 源项目范围：当前用户参与且为项目创建人（`project.create-by`）或项目管理员（`project.admin`）的项目；**允许跨团队**。
- 复制预估占用与**每项目最大空间**对比展示；超限不可完成创建（或不可再勾增项）。大体积复制走异步任务与进度反馈。
- Admin（系统超级管理员）侧栏新增「团队角色」模块：维护套餐；默认「普通团队」含团队最大人数 10、团队最大项目数 20、每项目最大空间 1G；真实团队绑定套餐，加人 / 建项目 / 复制灌入时强制校验。
- 不复制：项目名称 / Key / 简介 / 图标（新建表单填写）、API Key、出站推送配置、删除项目；一期不复制缺陷、计划、个人页签/工作台布局。
- 不推翻已有 ADR；跨团队复制时团队级用例类型/缺陷属性仍按 [[ADR-023-用例类型评审模板与缺陷属性归属团队]] 归属目标团队（见 design）。

## Capabilities

### New Capabilities

- `project-create-copy`：新建项目时可选从源项目按勾选项复制资产与配置（含预估体积、异步灌入与依赖规则）。
- `admin-team-plan-quota`：Admin 团队角色（套餐）CRUD、默认「普通团队」、团队绑定，以及人数 / 项目数 / 项目空间配额的强制校验。

### Modified Capabilities

- （无）现有 `openspec/specs/` 无「新建项目」或「团队配额」规格需改条款；本次以新能力覆盖。

## Impact

- 前端：`views/system/project/add.vue`（复制 UI）；Admin 新菜单与团队角色页；团队加人 / 项目列表创建入口的配额提示。
- 后端：`SysProjectService.insertSysProject` 扩展或创建后 copy Job；模块 / 用例 / 文档 / Git bare 复制与 ID remap；`ProjectCloudPushService` 估算口径可复用；Admin 团队角色 API 与配额校验拦截。
- 数据：新表（团队角色/套餐、团队绑定、可选项目已用空间计量）；Flyway 迁移；默认种子「普通团队」。
- 运维：磁盘占用增长（Git bare、文档文件）；复制任务失败重试与可观测性。
