## Why

不同团队对产品能力的取舍不同：有的只要缺陷、有的要把「交付物」叫成「模块」、有的要把文档上传压到系统上限以下。当前团队设置只有信息 / 用例 / 缺陷 / 成员四卡，模块显隐完全依赖角色菜单与项目 MCP 勾选，无法在团队层一刀切关掉能力，也无法统一改产品文案。需要在团队设置补齐各业务卡的「页面设置」，用硬闸门控制显示与 API，并支持前后端显示名与文档上传上限。

## What Changes

- 团队设置枢纽新增 **源码设置、交付物设置、文档设置** 卡片；原「用例设置」扩展为 **用例与计划设置**（保留类型 / 评审模板入口，并增加页面设置）。
- 上述各卡及现有 **缺陷设置** 均提供 **页面设置**：至少包含「显示模块」开关与「模块名称」；文档另含上传文件最大尺寸（不得超过系统后台上限）。
- **用例与计划** 共用一个显示开关（关则用例 + 计划一并不可见、不可调用）；显示名仍为 **两个输入框**（用例、计划可分别改名）。
- 「显示模块」关闭后：该团队下所有项目无论角色权限如何，侧栏 / 路由 / **相关 API（含 MCP）** 均不可用；跨模块关联属性隐藏（例如关用例与计划后缺陷不展示测试用例相关字段）；**工作台**依赖该模块的组件不渲染。允许全部业务模块关闭。
- 模块改名作用于 **前后端给人看的文案**（菜单、表单、提示、导出表头、MCP 指南正文等）；URL 段、表名、权限串、Open API 路径与 MCP 模块键 **不变**。
- 系统后台提供可配置的上传文件尺寸上限（自现有硬编码提升）；团队文档上传上限校验 `≤` 该值。
- 业务数据不因关模块而级联删除；重新开启后数据仍可用。
- 不推翻 ADR-014（MCP = 角色权限 ∩ 项目模块）；团队闸门作为更外层求交。

## Capabilities

### New Capabilities

- `team-module-page-settings`: 团队级功能模块开关、显示名别名、文档上传上限，以及枢纽新卡片 / 各卡页面设置入口与生效面（UI、API、跨模块字段、工作台、MCP 求交）。

### Modified Capabilities

- `team-case-defect-settings`: 枢纽卡片从「信息 / 用例 / 缺陷 / 成员」扩展；用例卡改为用例与计划并增加页面设置入口；废除「不得新增与页面设置相关的顶层业务卡」中与本变更冲突的约束（缺陷卡内页面设置入口保留）。
- `team-defect-page-settings`: 缺陷页面设置在现有视图 / 色阶 / 分享之外，增加「显示模块」与「模块名称」。
- `project-mcp-settings`: 有效 MCP 模块 = 原规则 ∩ 团队「显示模块」开启集合（用例与计划开关映射到 case + plan）。
- `project-workbench`: 团队关闭某功能模块后，工作台已放置或目录中依赖该模块的组件不显示。

## Impact

- 前端：`views/system/team/option/` 枢纽与各卡、各 `*-page-settings` 页；侧栏 / 路由守卫；缺陷 / 用例 / 计划等关联字段；工作台组件显隐；i18n 运行时别名；文档上传 `file-size`。
- 后端：`sys_team`（或等价）模块页面配置持久化；团队 GET/PUT API；按模块键拦截业务 API；`MessageSource` / 导出文案别名；`FileUploadService` 与系统配置上限；文档上传校验。
- MCP：有效模块求交；指南文案用团队别名。
- 系统管理：上传文件最大尺寸配置项。
- 文档：术语表 / 产品功能 / 接口清单 / 版本记录；可选 ADR（团队功能模块闸门）。
- 权限：页面设置读写与现有团队配置权限对齐（团队创建人 / 管理员对应菜单权限）。
