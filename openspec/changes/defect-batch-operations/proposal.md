## Why

缺陷列表目前只能对单条做指派、修复、驳回、通过、关闭、重开、删除；处理多条同质缺陷时需反复点行内按钮与弹窗，效率低。需要在表格模式下提供与单条规则一致的批量入口与批量填写弹窗。

## What Changes

- 缺陷页表格模式：在「新建缺陷」前增加「批量操作」下拉；Excel 模式隐藏该按钮。
- 表格增加勾选列；勾选范围仅当前页；勾选 ≥1 条即可使用批量入口。
- 批量动作：指派、修复、驳回、通过、关闭、重开、删除。菜单可用性按「选中状态是否一致」与「每条是否满足现有单条可见/权限规则（严格）」计算。
- 同状态：开放该状态下单条应有的动作（∩ 严格权限）。
- 混合状态：仅开放指派、关闭、删除（仍逐条严格；含已关闭则指派/关闭整项不可用）。
- 需描述/人员的动作：弹窗列出选中缺陷，支持逐行填写，也支持顶部「应用到全部」；字段严格复刻对应单条弹窗（不额外加处理人等字段）。
- 删除：确认框，不进入列表弹窗。
- 执行：前端串行调用现有单条 API；汇总成功/失败，不新增后端批量流转接口（本期）。

## Capabilities

### New Capabilities

- `defect-batch-operations`: 缺陷列表批量勾选、批量操作菜单可见性规则、批量弹窗（描述/人员逐行与批量赋值）、删除确认与串行提交结果反馈。

### Modified Capabilities

- （无）现有 `openspec/specs/` 中无缺陷批量流转的需求规格；单条流转规则不变，仅新增批量入口与编排。

## Impact

- 前端：`cat2bug-platform-ui/src/views/system/defect/index.vue`、`list/table.vue`；新建批量菜单与批量弹窗组件（可挂在 `components/Defect/`）；复用现有 `api/system/defect` 单条接口与 `DefectTools` 可见性逻辑。
- 后端：无新接口；沿用 `/system/defect/{id}/assign|repair|reject|pass|close|open` 与删除接口。
- UI 约定：列表工具条右侧操作区，对齐 `docs/04-UI规范/组件与交互约定.md`「列表页工具条」。
- 不推翻既有 ADR；不改 MCP 指南（本期仅网页）。
