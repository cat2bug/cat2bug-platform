# defect-batch-operations Specification

## Requirements

### Requirement: 表格模式提供批量操作入口

缺陷页在表格模式下 MUST 在工具条「新建缺陷」之前提供「批量操作」下拉。Excel 模式下 MUST NOT 显示该按钮。勾选范围 MUST 仅限当前页；勾选数量 ≥1 时批量入口 MUST 可交互（无勾选时 MUST 禁用或等价不可用）。

#### Scenario: 表格模式显示批量操作

- **WHEN** 用户处于缺陷表格视图且具备查看列表能力
- **THEN** 工具条在「新建缺陷」前显示「批量操作」下拉

#### Scenario: Excel 模式隐藏批量操作

- **WHEN** 用户切换到缺陷 Excel 视图
- **THEN** 「批量操作」按钮不可见

#### Scenario: 未勾选不可用

- **WHEN** 当前页没有任何缺陷被勾选
- **THEN** 「批量操作」不可执行菜单项（禁用按钮或菜单项全部不可用）

### Requirement: 批量菜单按状态集合与严格单条资格计算

系统 MUST 按与行内 `DefectTools` 相同的规则判定每条缺陷对某动作是否可用（状态、创建人/处理人、权限、未删除）。某菜单项仅当选中集合中每一条对该动作均可用时 MUST 启用。

当选中缺陷的状态全部相同：候选动作 MUST 为该状态下单条可能出现的动作集合（指派、修复、驳回、通过、关闭、重开、删除）再与严格资格求交。

当选中缺陷存在多种状态：候选动作 MUST 仅包含指派、关闭、删除，再与严格资格求交。

#### Scenario: 同状态待审核且均为当前处理人

- **WHEN** 用户勾选多条状态均为待审核、且自己是每条当前处理人的缺陷，并具备驳回/通过权限
- **THEN** 「驳回」「通过」菜单项可用（在严格规则满足时，「指派」「关闭」「删除」也可按各自规则可用）

#### Scenario: 同状态但部分无权限则动作禁用

- **WHEN** 用户勾选多条待审核缺陷，但对其中至少一条不是当前处理人
- **THEN** 「驳回」「通过」菜单项不可用

#### Scenario: 混合状态仅开放跨状态动作

- **WHEN** 用户勾选同时包含处理中与待审核的缺陷，且对每一条均满足指派资格
- **THEN** 「指派」可用；「驳回」「通过」「修复」「重开」不可用

#### Scenario: 混合状态含已关闭时指派关闭禁用

- **WHEN** 用户勾选包含已关闭与未关闭的缺陷
- **THEN** 「指派」「关闭」不可用（严格：并非每一条都可指派/关闭）；「删除」在每一条均满足删除资格时可用

### Requirement: 批量填写弹窗支持逐行与应用到全部

对指派、修复、驳回、通过、关闭、重开，系统 MUST 打开列出选中缺陷的弹窗。弹窗字段 MUST 与对应单条弹窗一致：

- 指派：处理人必填，描述可选
- 修复：审核人必填，描述可选
- 驳回：描述必填
- 通过：描述可选
- 关闭：描述必填
- 重开：描述必填，MUST NOT 增加处理人字段（复刻现单条）

弹窗 MUST 提供将顶部描述和/或人员值「应用到全部」行的能力；应用后用户 MUST 仍能逐行修改。提交前 MUST 按与单条相同的必填规则校验每一行。

#### Scenario: 批量指派应用到全部后再改一行

- **WHEN** 用户在批量指派弹窗顶部选择处理人并「应用到全部」，再修改其中一行的处理人后提交
- **THEN** 各缺陷分别使用其行上最终的处理人与描述调用指派接口

#### Scenario: 批量驳回缺少描述不可提交

- **WHEN** 用户打开批量驳回弹窗且至少一行描述为空
- **THEN** 提交被校验拦截，不得对描述为空的行调用驳回接口

### Requirement: 批量删除使用确认框

批量删除 MUST 使用确认对话框，MUST NOT 使用列表填写弹窗。确认后 MUST 对选中缺陷串行调用现有删除接口（或等价批量删除 API，若已有且语义为删除选中 id）。仅当每一条均满足删除资格时删除菜单 MUST 可用。

#### Scenario: 确认后删除选中缺陷

- **WHEN** 用户对均有权删除的选中缺陷选择「删除」并在确认框确认
- **THEN** 系统删除这些缺陷并反馈结果

### Requirement: 串行提交与结果汇总

除删除确认外的批量动作，以及删除确认后的执行，系统 MUST 对选中缺陷逐条调用现有单条接口，一条失败 MUST NOT 阻止继续处理其余条目。结束后 MUST 向用户汇总成功数量与失败数量；失败时 SHOULD 展示失败缺陷编号或原因。成功处理后 MUST 刷新当前列表并清除勾选。

#### Scenario: 部分失败仍处理其余

- **WHEN** 批量关闭 3 条缺陷，第 2 条接口返回失败
- **THEN** 第 1、3 条仍被尝试关闭，最终提示成功与失败数量
