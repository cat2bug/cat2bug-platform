# defect-merge-duplicates Specification

## Requirements

### Requirement: 合并抽屉左右分栏与主缺陷选定

系统 MUST 在用户从批量操作进入合并时打开合并抽屉：左侧为可编辑的合并结果表单（字段集合与缺陷编辑表单一致），右侧为进入时勾选的缺陷只读列表。右侧每条 MUST 提供「主缺陷」操作。用户点击「主缺陷」时，系统 MUST 将该源缺陷的全部可编辑字段写入左侧，并将该缺陷 id 记为 `masterDefectId`。若左侧已有内容，系统 MUST 先确认覆盖，用户取消则 MUST NOT 改写左侧或主 id。未选定主缺陷时，头部「合并」提交 MUST 不可用。

#### Scenario: 首次选定主缺陷写入左侧

- **WHEN** 用户打开合并抽屉且左侧尚无主缺陷内容，并点击右侧某条「主缺陷」
- **THEN** 左侧表单字段变为该缺陷的可编辑字段副本，且该缺陷成为主缺陷

#### Scenario: 再次选定主缺陷需确认覆盖

- **WHEN** 左侧已有主缺陷或已修改内容，用户点击另一条「主缺陷」并确认覆盖
- **THEN** 左侧被新源整单覆盖，主缺陷 id 切换为新源

#### Scenario: 取消覆盖保持原状

- **WHEN** 左侧已有内容，用户点击另一条「主缺陷」但在确认框取消
- **THEN** 左侧内容与主缺陷 id 不变

#### Scenario: 未定主不可提交

- **WHEN** 用户尚未成功选定主缺陷
- **THEN** 「合并」按钮禁用或提交被拦截

### Requirement: 单属性用此属性为替换而非拼接

当用户聚焦或点选左侧某一表单字段时，右侧列表中每条对应字段 MUST 着重高亮，并提供「用此属性」（或等价文案）。点击后系统 MUST 仅用该源缺陷的同一字段值**替换**左侧该字段；MUST NOT 将多条缺陷的同字段值拼接、追加或做集合并。描述、图片、附件、处理人等多值字段同样整字段替换。

#### Scenario: 用右侧某条标题覆盖左侧

- **WHEN** 用户聚焦左侧标题字段，并在右侧某条上点击该字段的「用此属性」
- **THEN** 左侧标题变为该源的标题，其它左侧字段不变

#### Scenario: 附件字段整字段替换

- **WHEN** 左侧已有附件 URL，用户对右侧另一条执行附件字段「用此属性」
- **THEN** 左侧附件变为该源的附件集合，不得把两条附件列表拼成更长列表

### Requirement: 合并提交单一接口浅合并且不可拆

确认合并时，客户端 MUST 调用单一合并 API，请求体包含 `projectId`、`masterDefectId`、完整源 id 集合（含主 id，长度 ≥2）以及左侧完整可写缺陷对象。服务端 MUST 在同一事务内：校验调用者具备 `system:defect:merge`、集合内缺陷同属该项目且未删除、主 id 属于集合；用提交体更新主缺陷；将其余源缺陷软删除（`del_flag=2`）；在主缺陷上记录合并审计日志（含被合并缺陷项目内编号）。系统 MUST NOT 提供将合并结果拆回多条缺陷的专用流程。本变更 MUST NOT 迁移从缺陷的日志、评论、计划项 CSV、甘特依赖边或分享记录。

#### Scenario: 成功合并两条

- **WHEN** 用户已选定主缺陷 #12，勾选集合为 #12 与 #18，调整左侧字段后确认合并且请求合法
- **THEN** #12 按左侧内容更新，#18 被软删，主缺陷带有合并审计日志，接口成功返回更新后的 #12

#### Scenario: 主 id 不在集合则失败

- **WHEN** 合并请求的 `masterDefectId` 不在 `sourceDefectIds` 中
- **THEN** 服务端拒绝请求且不修改任何缺陷

#### Scenario: 无合并权限则失败

- **WHEN** 调用者不具备 `system:defect:merge`
- **THEN** 服务端拒绝请求且不修改任何缺陷

#### Scenario: 部分源已删除则失败回滚

- **WHEN** 提交时集合中任一条已非未删除状态
- **THEN** 整个合并失败，主缺陷不得半更新

### Requirement: 独立合并权限点

系统 MUST 提供菜单/权限标识 `system:defect:merge`。仅当用户具备该权限时，批量「合并」入口与合并 API MUST 可用。合并成功 MUST NOT 额外要求 `system:defect:edit` 与 `system:defect:remove` 同时具备（实现可在服务端以 merge 权限完成更新与软删）。

#### Scenario: 有 merge 权限可见合并菜单

- **WHEN** 用户具备 `system:defect:merge` 且勾选 ≥2 条未删除缺陷
- **THEN** 批量操作中「合并」可用

#### Scenario: 无 merge 权限不可见或不可用

- **WHEN** 用户不具备 `system:defect:merge`
- **THEN** 「合并」菜单项不可用，且直接调用合并 API 被拒绝
