# 9001 质量管理体系 vs 29119-3 测试文档

## 一句话分工

| 目录 | 标准锚点 | Agent 产出物 |
|------|----------|--------------|
| [`../29119-3/`](../29119-3/README.md) | GB/T 38634.3 / ISO 29119-3 | **测试文档** 信息项模版（计划、说明、状态/完成报告、事件报告等） |
| [`./`](./README.md) | GB/T 19001 / ISO 9001 | **QMS 成文信息与记录** 模版（程序引用、内审、管评、纠正措施等） |

29119-3 回答：「测试活动 **产出什么文档、文档里有什么信息项**」。  
9001 回答：「组织如何用 **过程 + 记录** 证明体系在运行、在评价、在改进」。

## 为何审核常两者都要

- **客户/合同** 可能要求测试文档符合 29119 / 38634。  
- **认证机构** 按 19001/9001 检查是否有策划、实施、检查、改进的 **证据链**。  
- 同一份「测试完成报告」：  
  - 在 **29119-3** 视角：信息项是否完整（范围、结果、偏差等）。  
  - 在 **9001** 视角：是否按程序 **编制、评审、批准、分发、修订**，相关记录是否 **保留**。

## 对照示例

| 29119-3 测试文档（内容物） | 9001 侧常见记录（过程证据） | 关系 |
|---------------------------|----------------------------|------|
| 测试用例说明 / 测试说明（`test-specification.md`） | 测试用例 **评审记录**、变更记录 | 说明是交付物；评审记录证明 7 成文信息与 8 运行控制 |
| 测试计划（`test-plan.md`） | 计划 **批准**、重规划评审纪要 | 计划可 DSL 拉取 Cat2Bug 计划数据；批准栏在 QMS 记录 |
| 测试状态报告（`test-status-report.md`） | 项目例会纪要、管理层汇报记录 | 报告是度量输出；会议记录证明沟通与决策 |
| 测试完成报告（`test-completion-report.md`） | **管理评审** 输入材料清单中的测试总结附件 | 完成报告 ≠ 管评纪要 |
| 测试事件/缺陷报告（`test-incident-report.md`） | **纠正措施** 单、有效性验证 | 缺陷系统是运行证据；CAPA 闭环在 QMS 记录 |
| 测试方针 / 组织测试实践（skeleton） | 质量方针、质量目标、体系手册引用 | skeleton 对齐测试政策；方针批准在 5 领导 |

| 解释 Cat2Bug 能导出什么 | `cat2bug-qms-mapping.md` |

## 避免常见混淆

1. **不要把** 29119-3 的「测试计划」章节 **等同于** 「质量目标分解」—— 目标在 6 策划，测试计划是 8 运行的实现手段。  
2. **不要把** 缺陷清单 **等同于** 纠正措施记录 — 缺陷可触发 CAPA，但标准要求的措施分析与验证须 **单独保留**。  
3. **不要** 在 QMS 记录模版中复制 29119-3 全文 — 用 **引用 + 附件编号**（如：附件 B《XX 项目测试完成报告》Rev.3）。  
4. **不要** 为 QMS  invented `${api.capa.*}` 等变量 — 见 [cat2bug-qms-mapping.md](./cat2bug-qms-mapping.md)。
